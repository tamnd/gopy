# `Objects/call.c`

<CpyLink path="Objects/call.c" />

Every Python call — bytecode, C API, or `eval()` — eventually flows through
this file. It owns the vectorcall protocol (PEP 590): the
`PY_VECTORCALL_ARGUMENTS_OFFSET` flag, `PyVectorcall_NARGS`, and the
`_PyObject_VectorcallTstate` inner loop. The legacy `tp_call` slot is
served by `_PyObject_MakeTpCall`, which materializes the tuple/dict pair the
old ABI requires. Convenience wrappers (`PyObject_CallNoArgs`,
`PyObject_CallOneArg`, `PyObject_CallObject`) sit on top of vectorcall and
avoid allocations for the common low-arity cases.
`_PyStack_UnpackDict` and `_PyObject_VectorcallDict` bridge the two
calling conventions for callers that already have a `**kwargs` dict.
`call_function_ex` handles `CALL_FUNCTION_EX` by coercing `*args` to a tuple
and `**kwargs` to a dict before handing off.

### `_PyObject_MakeTpCall` — the legacy slow path (lines 200 to 260)

<CpyLink path="Objects/call.c" lines="200-260" />

When a callable's type does not set `Py_TPFLAGS_HAVE_VECTORCALL`, the C
array of arguments must be materialized into the `(args_tuple, kwargs_dict)`
shape the `tp_call` slot expects. `_PyObject_MakeTpCall` builds the tuple
from the first `nargs` elements of the stack array, then builds a dict from
the trailing `nkwargs` values whose keys come from the `kwnames` tuple:

```c
PyObject *
_PyObject_MakeTpCall(PyThreadState *tstate,
                     PyObject *callable,
                     PyObject *const *args, Py_ssize_t nargs,
                     PyObject *keywords)
{
    Py_ssize_t nkwargs = (keywords == NULL ? 0 : PyTuple_GET_SIZE(keywords));
    ...
    PyObject *argstuple = _PyTuple_FromArraySteal(args, nargs);
    ...
    PyObject *kwdict = NULL;
    if (nkwargs > 0) {
        kwdict = _PyDict_FromKeys(tstate, keywords, args + nargs, nkwargs);
        ...
    }
    PyObject *result = call(callable, argstuple, kwdict);
    ...
    return result;
}
```

gopy's `MakeTpCall` in `objects/call.go` replicates this exactly, switching
on the `keywords` type: a `*Tuple` means kwnames + trailing values (vectorcall
layout), while a `*Dict` means the caller already has a materialized dict and
the copy step is skipped.

### `PyObject_Vectorcall` and `PyObject_Call` (lines 323 to 430)

<CpyLink path="Objects/call.c" lines="323-430" />

`PyObject_Vectorcall` is the preferred public entry. It checks for the
`Vectorcall` slot first; if absent it falls through to `_PyObject_MakeTpCall`:

```c
PyObject *
PyObject_Vectorcall(PyObject *callable, PyObject *const *args,
                    size_t nargsf, PyObject *kwnames)
{
    PyThreadState *tstate = _PyThreadState_GET();
    return _PyObject_VectorcallTstate(tstate, callable, args, nargsf, kwnames);
}
```

`PyObject_Call` — the old ABI used by C extensions — inverts the flow: if
the callable has a vectorcall slot it converts the tuple/dict into C-array
form via `_PyVectorcall_Call`; only otherwise does it invoke `tp_call`
directly. This means vectorcall-capable types never go through `tp_call`
even when called from legacy code.

### `PyObject_CallOneArg` and `_PyObject_Call_Prepend` (lines 386 to 480)

<CpyLink path="Objects/call.c" lines="386-480" />

`PyObject_CallOneArg` reserves the slot before the argument array using the
`PY_VECTORCALL_ARGUMENTS_OFFSET` flag, letting vectorcall callees overwrite
`args[-1]` without allocation:

```c
PyObject *
PyObject_CallOneArg(PyObject *func, PyObject *arg)
{
    assert(arg != NULL);
    PyObject *const args[2] = {NULL, arg};  /* args[-1] reserved */
    size_t tstate_offset = (size_t)(PY_VECTORCALL_ARGUMENTS_OFFSET);
    return _PyObject_VectorcallTstate(tstate, func, &args[1],
                                      1 | tstate_offset, NULL);
}
```

`_PyObject_Call_Prepend` is the same pattern but for methods: it builds a
stack with `self` at slot 0 and the existing positional args behind it, then
calls `_PyObject_VectorcallDict` so keyword arguments from a dict are also
honored. gopy's `CallPrepend` in `objects/call.go` matches this behavior.
