`Objects/memoryobject.c` implements Python's `memoryview` type. The central representation is `PyMemoryViewObject`, which holds a `Py_buffer` descriptor carrying a raw pointer, byte length, element size, format string, number of dimensions, and per-dimension shape, stride, and suboffset arrays. An internal `_PyManagedBufferObject` wrapper lets multiple views share one root buffer without calling `bf_releasebuffer` prematurely.

## Reading

### PyMemoryViewObject and Py_buffer layout

`PyMemoryViewObject` wraps a `Py_buffer` directly by value. The `Py_buffer` struct carries everything needed to interpret an arbitrary memory region without reference to the exporting object.

```c
// CPython: Objects/memoryobject.c:1 (see Include/cpython/object.h for Py_buffer)
typedef struct {
    void      *buf;         /* pointer to raw memory                    */
    PyObject  *obj;         /* exporting object (owned ref)             */
    Py_ssize_t len;         /* total byte length                        */
    Py_ssize_t itemsize;    /* size of one element                      */
    int        readonly;
    int        ndim;        /* number of dimensions                     */
    char      *format;      /* struct-module format string              */
    Py_ssize_t *shape;      /* shape[ndim]                              */
    Py_ssize_t *strides;    /* strides[ndim] in bytes                   */
    Py_ssize_t *suboffsets; /* suboffsets[ndim] for indirect arrays     */
    void      *internal;
} Py_buffer;
```

The `PyBUF_*` flags passed to `bf_getbuffer` tell the exporter how much of this struct the consumer requires. `PyBUF_SIMPLE` requests only `buf` and `len`. `PyBUF_STRIDES` additionally requires `strides` to be filled in. `PyBUF_FORMAT` requires the format string. `PyBUF_WRITABLE` rejects read-only buffers.

### Release protocol

The release protocol ensures `bf_releasebuffer` is called exactly once per successful `bf_getbuffer`, regardless of how many views were derived from the same root.

```c
// CPython: Objects/memoryobject.c:481 memory_releasebuffer
static void
memory_releasebuffer(PyMemoryViewObject *self, Py_buffer *view)
{
    /* decrement the managed-buffer export count */
    _PyManagedBufferObject *mbuf = self->mbuf;
    if (--mbuf->exports == 0 && mbuf->master.obj != NULL) {
        PyBuffer_Release(&mbuf->master);  /* calls bf_releasebuffer once */
    }
}
```

A view created by slicing increments `mbuf->exports` at construction time. The exporting object is kept alive through `mbuf->master.obj` until the last view is released.

## gopy notes

- `objects/memoryview.go` models `Py_buffer` as a Go struct with `unsafe.Pointer` for `Buf`. The `shape` and `strides` slices are represented as `[]int` rather than `*Py_ssize_t` arrays.
- The managed-buffer two-level structure maps to a Go struct with a `sync/atomic` export counter, eliminating the need for the GIL during release.
- `unpack_single`'s format-code switch translates to a Go `switch` on `format[0]` using `unsafe.Pointer` casts to the appropriate Go integer or float type.
- `memory_cast` zero-copy behaviour is preserved: gopy creates a new `MemoryViewObject` sharing the same backing `[]byte` slice, adjusting only the format, itemsize, and shape fields.
- <CpyLink file="Objects/memoryobject.c" line={481}>memory_releasebuffer</CpyLink> is the reference for the export-count decrement and single-call release guarantee.
