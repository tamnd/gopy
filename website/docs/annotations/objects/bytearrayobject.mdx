# `Objects/bytearrayobject.c`

<CpyLink path="Objects/bytearrayobject.c" />

`bytearray` is a mutable sequence of integers in the range 0-255. Its internal
storage is a heap-allocated `char*` buffer (`ob_val`) that is kept separate
from the `PyByteArrayObject` struct. Two extra fields track the buffer: `ob_alloc`
holds the total capacity including the over-allocation headroom, and `ob_start`
is a pointer into `ob_val` that may be advanced past the front of the buffer
to implement cheap deletion from the beginning without copying. This is the
same strategy used by `bytes` for slice operations.

Mutations that would overflow the current capacity call `bytearray_resize`,
which applies the same `newsize + (newsize >> 3) + (3 or 6)` formula as
`list_resize`. While the buffer is exported via the buffer protocol
(`ob_exports > 0`), all mutations that would reallocate the buffer raise
`BufferError`. Reads and in-place modifications at fixed size are still
permitted.

## Reading

### Buffer layout and `bytearray_resize` (lines 100 to 300)

<CpyLink path="Objects/bytearrayobject.c" lines="100-300" />

The `PyByteArrayObject` layout has three storage-related fields:

```c
typedef struct {
    PyObject_VAR_HEAD
    Py_ssize_t ob_alloc;   /* How many bytes allocated in ob_val */
    char *ob_val;          /* Physical start of the heap buffer */
    char *ob_start;        /* Logical start (>= ob_val) */
    Py_ssize_t ob_exports; /* How many buffer views are active */
} PyByteArrayObject;
```

`ob_start` is a cursor into `ob_val`. Deleting bytes from the front advances
`ob_start` without copying. Appending to the back may trigger a `realloc` of
the `ob_val` block. After any `realloc`, `ob_start` must be reset to `ob_val`
because the pointer into the old block is no longer valid. `bytearray_resize`
handles this reset:

```c
int
bytearray_resize(PyByteArrayObject *self, Py_ssize_t requested_size)
{
    Py_ssize_t alloc = ...;  /* over-allocation formula */
    char *sval;
    Py_ssize_t logical_offset = self->ob_start - self->ob_val;

    if (logical_offset > 0) {
        /* Shift content back to the front before realloc */
        memmove(self->ob_val, self->ob_start, Py_SIZE(self));
        self->ob_start = self->ob_val;
    }
    sval = (char *)PyObject_Realloc(self->ob_val, alloc);
    ...
    self->ob_val = sval;
    self->ob_start = sval;
    self->ob_alloc = alloc;
    Py_SET_SIZE(self, requested_size);
    return 0;
}
```

The `memmove` step consolidates the buffer before `realloc` so that the
resulting block starts at offset zero. This pays off when the buffer is
frequently written to the front after `del ba[0]` calls.

### Mutation methods (lines 900 to 1300)

<CpyLink path="Objects/bytearrayobject.c" lines="900-1300" />

`bytearray_append` is the simplest mutation:

```c
static PyObject *
bytearray_append(PyByteArrayObject *self, PyObject *arg)
{
    int value;
    if (!_getbytevalue(arg, &value))
        return NULL;
    if (bytearray_resize(self, Py_SIZE(self) + 1) < 0)
        return NULL;
    self->ob_start[Py_SIZE(self) - 1] = value;
    Py_RETURN_NONE;
}
```

`bytearray_extend` is more complex: it checks `isinstance(iterable, bytes)`,
`isinstance(iterable, bytearray)`, and `PyObject_GetBuffer` to take a fast
path before falling back to a full iterator loop. The fast path copies the
source into the destination using `memcpy`.

`bytearray_iadd` (the `+=` operator) delegates to `bytearray_extend` and
returns `self`, allowing chained augmented assignments without allocating a
new object.

### Buffer protocol (lines 2500 to 2800)

<CpyLink path="Objects/bytearrayobject.c" lines="2500-2800" />

`bytearray_getbuffer` exposes the live buffer to external consumers via the
`Py_buffer` protocol:

```c
static int
bytearray_getbuffer(PyByteArrayObject *obj, Py_buffer *view, int flags)
{
    if (view == NULL) {
        obj->ob_exports++;
        return 0;
    }
    int ret = PyBuffer_FillInfo(view, (PyObject *)obj,
                                PyByteArray_AS_STRING(obj),
                                Py_SIZE(obj), 0, flags);
    if (ret == 0)
        obj->ob_exports++;
    return ret;
}
```

Each successful `getbuffer` call increments `ob_exports`. `bytearray_releasebuffer`
decrements it. Any `bytearray_resize` call first checks `ob_exports`:

```c
if (self->ob_exports > 0 && requested_size != Py_SIZE(self)) {
    PyErr_SetString(PyExc_BufferError,
        "Existing exports of data: object cannot be re-sized");
    return -1;
}
```

In-place byte writes (e.g. `ba[0] = 42`) do not resize and are always
permitted regardless of `ob_exports`.

## gopy mirror

`objects/bytearray.go`. The `ob_val`/`ob_start`/`ob_alloc` layout maps to
Go fields `val []byte`, `start int`, `alloc int`. The resize formula is an
exact port. Buffer export tracking is a plain `int32` counter guarded by the
GIL in the same way as CPython. The bytes-searching helpers delegate to
`strings.Index` and `bytes.Index`.

## CPython 3.14 changes

`bytearray` has been stable since 3.0. The `ob_start` offset trick was
present in the original `bytearray` implementation (PEP 3137). No 3.14-specific
changes affect the core buffer or mutation logic.
