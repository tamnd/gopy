`exceptions.c` owns the entire built-in exception type tree. It defines the
`BaseException` C struct, stamps out the ~40 leaf classes via macros, adds
field-rich subtypes (`OSError`, `SyntaxError`, `UnicodeError`), and registers
all types into the `builtins` dict through `_PyExc_InitState`.

## Reading

### BaseException struct

Every exception begins with this layout. The four chain fields implement
PEP 3134 (implicit `__context__`) and PEP 415 (explicit `raise X from Y`
which sets `__cause__` and flips `suppress_context`).

```c
// CPython: Objects/exceptions.c:16 PyBaseExceptionObject
typedef struct {
    PyObject_HEAD
    PyObject *dict;              /* instance __dict__, lazily allocated    */
    PyObject *args;              /* tuple of constructor positional args   */
    PyObject *notes;             /* list[str] from add_note(), or NULL     */
    PyObject *traceback;         /* __traceback__ frame chain              */
    PyObject *context;           /* __context__: active exception at raise */
    PyObject *cause;             /* __cause__: from raise X from Y         */
    char      suppress_context;  /* True when __cause__ was set explicitly  */
} PyBaseExceptionObject;
```

`BaseException_new` zero-inits the struct and sets `args = ()`. `notes` stays
`NULL` until `add_note()` is called for the first time.

### _PyExc_InitState and EXC_MODULE_INIT

`_PyExc_InitState` is called during interpreter startup. It iterates over a
static table of `(PyObject **, PyTypeObject *)` pairs and calls
`PyDict_SetItemString` to insert each exception type into `builtins.__dict__`.

```c
// CPython: Objects/exceptions.c:2250 _PyExc_InitState (simplified)
int
_PyExc_InitState(PyInterpreterState *interp)
{
    /* Each entry was registered via EXC_MODULE_INIT macro. */
    for (size_t i = 0; i < Py_ARRAY_LENGTH(static_exceptions); i++) {
        struct static_exception se = static_exceptions[i];
        if (PyDict_SetItemString(builtins_dict, se.name,
                                 (PyObject *)se.exc) < 0)
            return -1;
    }
    return 0;
}
```

The `SimpleExtendsException(EXCBASE, EXCNAME, EXCDOC)` macro near line 851
defines a `PyTypeObject` with `tp_base = &EXCBASE` and no extra C fields,
covering classes like `ValueError`, `RuntimeError`, and `LookupError`.

### StopIteration.value

Generators and coroutines signal their return value through
`StopIteration.value`. `StopIteration_init` pulls the first positional
argument out of `args` and stores it in a dedicated slot so the VM can read it
without re-indexing `args`.

```c
// CPython: Objects/exceptions.c:1322 StopIteration_init
static int
StopIteration_init(PyStopIterationObject *self,
                   PyObject *args, PyObject *kwds)
{
    if (BaseException_init((PyBaseExceptionObject *)self, args, kwds) == -1)
        return -1;

    PyObject *value = Py_None;
    if (PyTuple_GET_SIZE(args) >= 1)
        value = PyTuple_GET_ITEM(args, 0);

    Py_INCREF(value);
    Py_XDECREF(self->value);
    self->value = value;
    return 0;
}
```

### ExceptionGroup subgroup / split

`ExceptionGroup.subgroup(condition)` walks the nested exception tree and
returns a new group containing only the leaves that satisfy `condition`, or
`None` if nothing matches.

```c
// CPython: Objects/exceptions.c:2050 exceptiongroup_subgroup (simplified)
static PyObject *
exceptiongroup_subgroup(PyObject *self, PyObject *condition)
{
    PyBaseExceptionGroupObject *eg = (PyBaseExceptionGroupObject *)self;
    PyObject *result_excs = PyList_New(0);

    for (Py_ssize_t i = 0; i < PyTuple_GET_SIZE(eg->excs); i++) {
        PyObject *exc = PyTuple_GET_ITEM(eg->excs, i);
        if (PyObject_IsInstance(exc,
                (PyObject *)&_PyExc_BaseExceptionGroup)) {
            PyObject *sub = exceptiongroup_subgroup(exc, condition);
            if (sub != Py_None)
                PyList_Append(result_excs, sub);
            Py_DECREF(sub);
        } else {
            int matched = PyObject_IsTrue(
                PyObject_CallOneArg(condition, exc));
            if (matched > 0)
                PyList_Append(result_excs, exc);
        }
    }

    if (PyList_GET_SIZE(result_excs) == 0) {
        Py_DECREF(result_excs);
        return Py_NewRef(Py_None);
    }
    PyObject *excs_tuple = PySequence_Tuple(result_excs);
    Py_DECREF(result_excs);
    return _PyObject_CallMethod(self, &_Py_ID(derive), "O", excs_tuple);
}
```

`split(condition)` runs the same walk twice and returns `(match, rest)`. The
`derive` hook lets subclasses override tree reconstruction, defaulting to
`type(self)(self.message, excs)`.

## gopy notes

- `BaseException` in gopy is `objects.BaseException` in `objects/exception.go`,
  with fields mirroring the C struct one-for-one. `args` is `*Tuple`,
  `traceback` is `*Traceback`, and `context` / `cause` are `Object` interfaces.
- `PyErr_NewException` maps to `objects.NewExceptionClass`. Module-prefix
  splitting and `__module__` injection are both implemented.
- `StopIteration.Value` is read by `vm.evalFrame` at `RETURN_VALUE` when the
  active frame is a generator or coroutine. It is set via
  `objects.NewStopIteration(val)`.
- `OSError` subclass dispatch (mapping `errno` values to `FileNotFoundError`,
  `PermissionError`, etc.) lives in a `var errnoToExcType map[int]*Type` table
  populated at `init` time.
- `ExceptionGroup` and `BaseExceptionGroup` structs exist; the `subgroup`,
  `split`, and `derive` tree walk is stubbed pending a full port.

## CPython 3.14 changes

- `__notes__` (`add_note()`) was added in 3.11 (PEP 678) and is stable in 3.14.
- `ExceptionGroup` / `BaseExceptionGroup` landed in 3.11 (PEP 654); 3.14 adds
  no structural changes but fixes several edge cases in `split` when the group
  tree contains mixed `Exception` and `BaseException` leaves.
- The `OSError` constructor gained stricter validation in 3.12 preventing
  positional-only use when `errno` is a non-integer; that restriction holds in
  3.14.
- `_PyExc_InitState` replaced the older module-level `_PyExc_Init` entry point
  in 3.12 to support sub-interpreter isolation.
