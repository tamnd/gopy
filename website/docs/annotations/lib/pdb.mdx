# `Lib/pdb.py`

<CpyLink path="Lib/pdb.py" />

`pdb` is the standard interactive source debugger. It inherits from two
base classes in a single `class Pdb(bdb.Bdb, cmd.Cmd)` declaration:
`bdb.Bdb` owns the breakpoint table and the tracing hook
(`sys.settrace`); `cmd.Cmd` owns the REPL loop that reads lines, splits
off the first word, and calls `do_<command>(arg)`.

The file also provides four module-level entry points used by most
callers: `set_trace`, `post_mortem`, `pm`, and `run`/`runeval`/`runcall`.
A restart mechanism preserves the current breakpoint table across
`exec(restart_cmd)` calls so that iterative debugging sessions survive
source changes.

In CPython 3.14 the `displayhook` and `completenames` overrides use the
new `annotationlib` API, and `_getval_except` was extended to show
deferred annotation failures cleanly.


The two-base `__init__` order matters: `bdb.Bdb.__init__` installs the
`sys.settrace` hook and sets up the breakpoint machinery; `cmd.Cmd.__init__`
sets up readline integration. `.pdbrc` lines are collected into
`self.rcLines` and replayed via `execRcLines` on the first call to
`interaction`. A per-directory `.pdbrc` is tried after the home-directory
one, so project-local debugger macros can override the user defaults.

### `interaction` and the command loop (lines 431 to 560)

<CpyLink path="Lib/pdb.py" lines="431-560" />

```python
def interaction(self, frame, traceback):
    ...
    self.setup(frame, traceback)
    self.print_stack_entry(self.stack[self.curindex])
    self.execRcLines()
    self._cmdloop()
    self.forget()

def _cmdloop(self):
    while True:
        try:
            # keyboard interrupts allow for a graceful exit
            self.cmdloop()
            break
        except KeyboardInterrupt:
            print('--KeyboardInterrupt--', file=self.stdout)
```

`interaction` is the re-entry point that `user_line`, `user_return`,
and `user_exception` all call. It prints the current location, drains
any pending `.pdbrc` commands, then hands control to `cmd.Cmd.cmdloop`.
`cmdloop` reads one line at a time from `self.stdin`, strips whitespace,
calls `onecmd`, and loops until `onecmd` returns `True` (which the
`do_continue`, `do_step`, and similar commands do). `KeyboardInterrupt`
during readline is caught in `_cmdloop` so the user gets a clean
`--KeyboardInterrupt--` banner instead of a traceback.

### `_getval` and expression evaluation (lines 561 to 670)

<CpyLink path="Lib/pdb.py" lines="561-670" />

```python
def _getval(self, arg):
    try:
        return eval(arg, self.curframe.f_globals, self.curframe_locals)
    except:
        self._error_exc()
        raise

def _getval_except(self, arg, frame=None):
    try:
        if frame is None:
            return eval(arg, self.curframe.f_globals, self.curframe_locals)
        else:
            return eval(arg, frame.f_globals, frame.f_locals)
    except:
        exc = sys.exception()
        return _rstr('** raised %s **' % _repr_exc(exc))
```

All command handlers that evaluate user-supplied expressions go through
`_getval`. The frame's `f_globals` and `f_locals` are used as the
evaluation namespace so the user sees exactly the same names the paused
code sees. `_getval_except` is the non-raising variant used by
`do_display` to silently show `** raised ExcType **` when a watched
expression is temporarily unevaluable, rather than aborting the
display loop.
