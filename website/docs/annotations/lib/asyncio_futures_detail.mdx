`futures.py` defines `Future`, the primitive awaitable that underpins every asyncio coroutine suspension. `Task` is a `Future` subclass. Understanding `Future` state transitions is prerequisite to reading the task step loop.

## Reading

### State machine

A `Future` moves through states in one direction only: `_PENDING` to either `_CANCELLED` or `_FINISHED`. No transition goes backward. `set_result` and `set_exception` both require `_PENDING`; a second call raises `InvalidStateError`.

```python
# CPython: Lib/asyncio/futures.py:201 Future.set_result
def set_result(self, result):
    if self._state != _PENDING:
        raise exceptions.InvalidStateError(
            f'{self._state}: {self!r}')
    self._result = result
    self._state = _FINISHED
    self.__schedule_callbacks()
```

### `cancel` and `_must_cancel`

`cancel` is more subtle than `set_result`. If the future is already done, it is a no-op and returns `False`. Otherwise it sets `_state = _CANCELLED` and schedules callbacks. `Task` overrides `cancel` to set `_must_cancel` and inject a `CancelledError` into the running coroutine on the next step.

```python
# CPython: Lib/asyncio/futures.py:175 Future.cancel
def cancel(self, msg=None):
    self.__log_traceback = False
    if self._state != _PENDING:
        return False
    self._state = _CANCELLED
    self._cancel_message = msg
    self.__schedule_callbacks()
    return True
```

### `result` and exception unwrapping

`result()` is the only way to retrieve the value. If the future was cancelled, it raises `CancelledError`. If `set_exception` was called, it re-raises the stored exception. This means `await fut` either returns the value or propagates the exception directly into the waiting coroutine frame.

```python
# CPython: Lib/asyncio/futures.py:261 Future.result
def result(self):
    if self._state == _CANCELLED:
        exc = self._make_cancelled_error()
        raise exc
    if self._state != _FINISHED:
        raise exceptions.InvalidStateError(
            f'Result is not ready for {self!r}')
    self.__log_traceback = False
    if self._exception is not None:
        raise self._exception.with_traceback(
            self._exception_tb)
    return self._result
```

### `__await__` and the yield protocol

`Task._step` drives the coroutine by calling `send(None)`. When the coroutine hits `await fut`, Python calls `fut.__await__()`. The generator yields `self` back to `_step`, which registers a wakeup callback on the future. When the future completes, the callback calls `_step` again and the coroutine resumes via `send(result)`.

```python
# CPython: Lib/asyncio/futures.py:390 Future.__iter__
def __iter__(self):
    if not self.done():
        self._asyncio_future_blocking = True
        yield self   # <-- received by Task._step
    if not self.done():
        raise RuntimeError(
            "await wasn't used with future")
    return self.result()

__await__ = __iter__
```

## gopy notes

- The three sentinel strings (`_PENDING`, `_CANCELLED`, `_FINISHED`) should become a Go `iota` enum. State transitions are the same four one-way edges.
- `_schedule_callbacks` appends each callback to `loop._ready` via `loop.call_soon`; gopy must do the same (append to the ready queue, not call directly) to preserve ordering guarantees.
- `_Future__log_traceback` (name-mangled) controls whether an unhandled-exception warning is emitted on GC. gopy should hook a finalizer for the same purpose when debug mode is on.
- The `_asyncio_future_blocking` flag on the yielded object is how `Task._step` distinguishes a legitimate future yield from an accidental raw `yield`.

## CPython 3.14 changes

- `Future.cancel` now accepts a `msg` keyword argument (added in 3.9, stabilised). The message is forwarded to `CancelledError` and appears in tracebacks.
- The C accelerator (`_asyncio` extension module) shadows this pure-Python class at import time. The pure-Python version remains the canonical reference; gopy ports from it.
- `set_exception` now rejects `StopIteration` subclasses explicitly, raising `TypeError`, to prevent the exception from silently terminating a `for` loop over an async iterator.
