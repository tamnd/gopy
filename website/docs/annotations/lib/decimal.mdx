# `Lib/decimal.py`

<CpyLink path="Lib/decimal.py" />

`Lib/decimal.py` is the pure-Python reference implementation of the IBM
General Decimal Arithmetic specification. In practice CPython loads the C
accelerator `Modules/_decimal/` whenever it is available; this file is only
executed when that extension is absent (e.g., in restricted or cross-compiled
environments). It is the normative source from which the C extension's
behaviour is defined, and reading it is the clearest path to understanding
the full semantics.

A `Decimal` is stored as three fields: an integer coefficient (a Python `int`),
a signed integer exponent, and a sign bit. Special values (`Inf`, `-Inf`,
`NaN`, `sNaN`) are represented by sentinel strings in place of the integer
coefficient. Every arithmetic operation queries the current thread-local
`Context` for precision, rounding mode, and trap settings, adjusting the
result accordingly and raising (or trapping) signals as needed.

`Context` carries eight attributes: `prec` (precision in digits, default 28),
`rounding` (one of the eight `ROUND_*` constants), `Emin` / `Emax` (exponent
limits), `capitals` (whether `E` or `e` is used in exponent notation),
`clamp`, `traps` (a dict of signal class to boolean), and `flags` (set of
signals raised since the last clear). Thread-local access goes through
`decimal.getcontext()` / `decimal.setcontext()` / `decimal.localcontext()`.

```python
class InvalidOperation(DecimalException):
    def handle(self, context, *args):

            return ans._fix_nan(context)
        return context._raise_error(InvalidOperation)

# Inside Context:
def _raise_error(self, condition, explanation=None, *args):
    error = _conditions[condition]
    self.flags[condition] = 1
    if not self.traps[condition]:
        return condition().handle(self, *args)
    else:
        raise error(explanation)
```

The signal model follows the IBM specification directly. Each signal class has
a `handle` classmethod that is called when the signal fires but no trap is
set. Most `handle` implementations return `NaN` or a context-appropriate
substitute. When a trap is set, `_raise_error` raises the corresponding
Python exception instead. This two-path design lets production financial code
run in trap-free mode collecting flags for post-hoc auditing, while
interactive code gets immediate exceptions.

### `Decimal` construction from string (lines 351 to 700)

<CpyLink path="Lib/decimal.py" lines="351-700" />

```python
class Decimal:
    def __new__(cls, value="0", context=None):
        ...
        if isinstance(value, str):
            m = _parser(value.strip())
            if m is None:
                if context is None:
                    context = getcontext()
                return context._raise_error(ConversionSyntax,
                    "%s is not a valid Decimal string" % value)
            sign = int(m.group('sign') == '-')
            intpart = m.group('int')
            fracpart = m.group('frac') or ''
            exp = int(m.group('exp') or 0)
            if intpart is not None:
                # finite number
                coeff = int(intpart + fracpart)
                exp -= len(fracpart)
                return cls._from_triple(sign, str(coeff), exp)
            ...
```

`_parser` is a compiled regex (`re.compile`) covering the full General
Decimal Arithmetic string grammar: optional sign, integer and fractional
decimal digits, optional exponent, and the special-value literals `Infinity`,
`NaN`, and `sNaN`. A leading/trailing `strip()` tolerates the whitespace
that CPython's `int()` constructor also accepts. Infinities and NaN payloads
take a separate branch that bypasses the exponent arithmetic.

```python
def __str__(self, eng=False, context=None):
    sign = ['', '-'][self._sign]
    if self._is_special:
        if self._exp == 'F':
            return sign + 'Infinity'
        elif self._exp == 'n':
            return sign + 'NaN' + self._int
        else:  # sNaN
            return sign + 'sNaN' + self._int
    # Finite number
    leftdigits = self._exp + len(self._int)
    if self._exp <= 0 and leftdigits > -6:
        dotplace = leftdigits
    elif not eng:
        dotplace = 1
    elif self._int == '0':
        dotplace = (leftdigits + 1) % 3 - 1
    else:
        dotplace = (leftdigits - 1) % 3 + 1
    ...
```

The formatting logic implements the exact coefficient/exponent arithmetic
from the General Decimal Arithmetic specification section 5.12. The `eng`
flag is the only difference between `__str__` and `to_eng_string`: when
`True`, the dot placement is shifted so that the exponent is always a
multiple of three, matching engineering notation conventions. `__format__`
calls this underlying machinery after parsing the format spec.

### Thread-local context management (lines 5701 to 6000)

<CpyLink path="Lib/decimal.py" lines="5701-6000" />

```python
_context_locals = threading.local()

def getcontext():
    try:
        return _context_locals.context
    except AttributeError:
        context = Context()
        _context_locals.context = context
        return context

def setcontext(context):
    _context_locals.context = context

class localcontext:
    def __init__(self, ctx=None, **kwargs):
        self.ctx = ctx or getcontext().copy()
        for key, value in kwargs.items():
            setattr(self.ctx, key, value)
    def __enter__(self):
        self._save = getcontext()
        setcontext(self.ctx)
        return self.ctx
    def __exit__(self, *args):
        setcontext(self._save)
```

`_context_locals` is a `threading.local` instance. The first call to
`getcontext()` on a new thread creates a copy of the process-level
`DefaultContext` and attaches it to the thread. `localcontext` is a context
manager; the `with decimal.localcontext() as ctx:` pattern is the idiomatic
way to perform a calculation at a different precision without mutating the
thread context permanently. Keyword arguments to `localcontext()` are applied
directly to the copied context before `__enter__` returns it.
