# `Lib/zipfile/__init__.py`

<CpyLink path="Lib/zipfile/__init__.py" />

The ZIP archive implementation. The module is self-contained: it reads and
writes the binary format defined in the PKZIP Application Note without
depending on any extension module beyond `zlib`, `bz2`, and `lzma` for
compression. `zipimport` (C extension) also reads ZIP files but uses a
separate code path.

The public API is built around two classes. `ZipInfo` carries per-member
metadata exactly as stored in the Central Directory: filename,
`date_time`, `compress_type`, `file_size`, `compress_size`, CRC-32,
`extra`, and `comment`. `ZipFile` owns the archive file descriptor and
exposes `open`, `read`, `write`, `writestr`, `extract`, `extractall`,
`namelist`, and `infolist`.

Four compression constants are defined: `ZIP_STORED = 0` (no compression),
`ZIP_DEFLATED = 8` (zlib), `ZIP_BZIP2 = 12`, and `ZIP_LZMA = 14`. The
default is `ZIP_STORED`; callers pass `compression=ZIP_DEFLATED` to
`ZipFile.__init__` or to individual `write` / `writestr` calls.

ZIP64 extensions are enabled automatically when a single entry exceeds
4 GB or when the entry count would overflow the 16-bit field in the
End-of-Central-Directory record.

```python
        ...
        x = ZipInfo(fname)
        x.extra = extra

        x.header_offset = struct.unpack_from('<q', extra_data)[0]  # ZIP64

```

`_RealGetContents` is the parser. It first calls `_EndRecData` which
seeks backward from the end of the file to find the End-of-Central-Directory
signature `PK\x05\x06` (possibly preceded by a Zip64 EOCD locator). Once
the CD offset is known, the Central Directory records are read in a loop and
converted to `ZipInfo` objects. The `concat` variable absorbs any
prepended payload such as a self-extracting stub, which shifts all offsets
by a fixed amount. ZIP64 extra-field records override the 32-bit fields when
sizes exceed `0xFFFFFFFF`.

`open` in read mode positions a `_SharedFile` wrapper at the Local File
Header for the requested member and constructs a `_ZipReadfile` that
decompresses on the fly. `_SharedFile` serialises concurrent reads
through `self._lock` so that the archive's single file descriptor can be
shared. In write mode `_open_to_write` writes the Local File Header
immediately (with placeholder sizes) and returns a `_ZipWriteFile` whose
`close` method patches the sizes and CRC back in via a seek.

`_write_end_record` is called by `close()` after all member writes are
complete. It iterates `self.filelist` to emit one 46-byte Central
Directory record per member (plus variable-length filename and extra
fields). When any member size exceeded 4 GB, or when the entry count
exceeds 65535, the function emits a Zip64 EOCD record plus the Zip64
EOCD locator before the standard EOCD. The standard EOCD fields that
overflow are set to `0xFFFF` / `0xFFFFFFFF` per the spec.

### `ZipInfo._decodeExtra` and ZIP64 sub-record (lines 401 to 550)

<CpyLink path="Lib/zipfile/__init__.py" lines="401-550" />

```python
def _decodeExtra(self, filesize_unknown=False):
    extra = self.extra
    unpack = struct.unpack
    while len(extra) >= 4:
        tp, ln = unpack('<HH', extra[:4])
        if tp == 0x0001:   # Zip64 extended information
            counts = ln // 8
            if filesize_unknown or self.file_size in (0xFFFFFFFF, -1):
                self.file_size = unpack('<Q', extra[4:12])[0]
                extra = extra[4+ln:]
                continue
            if counts >= 1:
                self.file_size    = unpack('<Q', extra[4:12])[0]
            if counts >= 2:
                self.compress_size = unpack('<Q', extra[12:20])[0]
            if counts >= 3:
                self.header_offset = unpack('<Q', extra[20:28])[0]
        elif tp == 0x000d:  # UNIX uid/gid
            ...
        extra = extra[4+ln:]
```

Extra fields use a tag-length-value encoding where each record starts
with a 2-byte tag and 2-byte length. Tag `0x0001` is the ZIP64 extended
information sub-record that overrides the four 32-bit Central Directory
fields (`file_size`, `compress_size`, `header_offset`, disk start) with
64-bit values. The number of 8-byte fields present depends on which 32-bit
fields held the sentinel value `0xFFFFFFFF` in the main record. Tag
`0x7875` carries UNIX uid/gid for permission-preserving extraction.
