`TestCase`, the base class every test suite subclasses, along with the full
assertion library, skip decorators, `subTest`, and the internal `_Outcome`
object that accumulates per-method results.

### `_Outcome` and `testPartExecutor`

```python
# CPython: Lib/unittest/case.py:45 _Outcome
class _Outcome(object):
    def __init__(self, result=None):
        self.expecting_failure = False
        self.result = result
        self.result_supports_subtests = hasattr(result, "addSubTest")
        self.success = True
        self.expectedFailure = None

    @contextlib.contextmanager
    def testPartExecutor(self, test_case, subTest=False):
        old_success = self.success
        self.success = True
        try:
            yield
        except KeyboardInterrupt:
            raise
        except SkipTest as e:
            self.success = False
            _addSkip(self.result, test_case, str(e))
        except _ShouldStop:
            pass
        except:
            exc_info = sys.exc_info()
            if self.expecting_failure:
                self.expectedFailure = exc_info
            else:
                self.success = False
                if subTest:
                    self.result.addSubTest(test_case.test_case, test_case, exc_info)
                else:
                    _addError(self.result, test_case, exc_info)
            exc_info = None
        else:
            if subTest and self.success:
                self.result.addSubTest(test_case.test_case, test_case, None)
        finally:
            self.success = self.success and old_success
```

`_Outcome` is a private accumulator. One instance is created per call to
`TestCase.run()`. The `testPartExecutor` context manager wraps each phase
(setUp, the test method, tearDown) and routes exceptions to the right
`result.addXxx` method. The `old_success` save-and-restore lets tearDown
failures mark the test failed even if setUp succeeded.

### `TestCase.run` lifecycle

```python
# CPython: Lib/unittest/case.py:634 TestCase.run
def run(self, result=None):
    ...
    result.startTest(self)
    try:
        ...
        outcome = _Outcome(result)
        try:
            self._outcome = outcome
            with outcome.testPartExecutor(self):
                self._callSetUp()
            if outcome.success:
                outcome.expecting_failure = expecting_failure
                with outcome.testPartExecutor(self):
                    self._callTestMethod(testMethod)
                outcome.expecting_failure = False
                with outcome.testPartExecutor(self):
                    self._callTearDown()
            self.doCleanups()
            ...
            if outcome.success:
                if expecting_failure:
                    if outcome.expectedFailure:
                        self._addExpectedFailure(result, outcome.expectedFailure)
                    else:
                        self._addUnexpectedSuccess(result)
                else:
                    result.addSuccess(self)
            return result
        finally:
            outcome.expectedFailure = None
            outcome = None
            self._outcome = None
    finally:
        result.stopTest(self)
```

The three phases (setUp, method, tearDown) are each wrapped by
`testPartExecutor`. If setUp fails, the method and tearDown are skipped, but
`doCleanups` always runs. The `expecting_failure` flag is toggled around the
method call only, so a failure in setUp is never treated as an expected failure.

### `subTest` context manager

```python
# CPython: Lib/unittest/case.py:546 TestCase.subTest
@contextlib.contextmanager
def subTest(self, msg=_subtest_msg_sentinel, **params):
    if self._outcome is None or not self._outcome.result_supports_subtests:
        yield
        return
    parent = self._subtest
    if parent is None:
        params_map = _OrderedChainMap(params)
    else:
        params_map = parent.params.new_child(params)
    self._subtest = _SubTest(self, msg, params_map)
    try:
        with self._outcome.testPartExecutor(self._subtest, subTest=True):
            yield
        ...
    finally:
        self._subtest = parent
```

`subTest` allows multiple independent assertions within one test method. Each
sub-test gets its own `_SubTest` instance. Failures are reported individually
but do not abort the enclosing test method. If `result` does not implement
`addSubTest`, the whole block degrades to a no-op yield.

### Skip decorators

```python
# CPython: Lib/unittest/case.py:157 skip
def skip(reason):
    def decorator(test_item):
        if not isinstance(test_item, type):
            @functools.wraps(test_item)
            def skip_wrapper(*args, **kwargs):
                raise SkipTest(reason)
            test_item = skip_wrapper
        test_item.__unittest_skip__ = True
        test_item.__unittest_skip_why__ = reason
        return test_item
    if isinstance(reason, types.FunctionType):
        test_item = reason
        reason = ''
        return decorator(test_item)
    return decorator
```

`skip` can be used as `@skip("reason")` or bare `@skip`. The bare form is
detected by checking whether `reason` is a function. The `__unittest_skip__`
attribute is read by `TestCase.run` at line 648 before the lifecycle begins.

## gopy notes

The `_Outcome` accumulator is a central porting target. gopy needs an
equivalent Go struct that holds success state and routes panics or returned
errors to `TestResult`. The `testPartExecutor` wrapping pattern maps onto
a Go `defer`-based recovery block, but the `subTest` nesting (via `_subtest`
pointer and `_OrderedChainMap`) requires a linked-list of sub-test contexts.

The `__unittest_skip__` attribute protocol is a good candidate for a Go
interface method rather than an attribute check, since Go has no
`getattr`-style dynamic dispatch.

## CPython 3.14 changes

3.14 added `_callTestMethod` at line 614 as a proper override hook (previously
it was inlined). This lets async subclasses override just that step.
`_AssertNotWarnsContext` was added in 3.13 and is present here unchanged.
The `@skip` decorator gained bare-decorator support (no parentheses) in 3.12
and is unchanged in 3.14.
