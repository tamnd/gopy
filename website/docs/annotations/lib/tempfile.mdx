# `Lib/tempfile.py`

<CpyLink path="Lib/tempfile.py" />

`tempfile` is entirely pure Python and relies only on `os`, `io`, and
`shutil` from the standard library. It provides six public entry points:

- `mkstemp` / `mkdtemp` — low-level primitives that return a file
  descriptor + path or a directory path without any cleanup machinery.
- `NamedTemporaryFile` — an open file-like wrapper whose underlying path
  is visible on the file system; deleted on `close()` unless
  `delete=False`.
- `TemporaryFile` — on POSIX, `open()` + immediate `os.unlink()`; on
  Windows, falls back to `NamedTemporaryFile` because Windows does not
  allow unlinking an open file.
- `SpooledTemporaryFile` — buffers in a `BytesIO` / `StringIO` until a
  `max_size` threshold is crossed, then spills to a real `NamedTemporaryFile`.
- `TemporaryDirectory` — wraps `mkdtemp` and deletes the tree on
  `__exit__` or `cleanup()`; supports `ignore_cleanup_errors` and
  a custom `onexc` handler.

All file-creating helpers share the same name-generation strategy:
`_RandomNameSequence` yields names built from `base64.urlsafe_b64encode(os.urandom(8))`
so that each call is statistically unique without any global counter or
lock.

In 3.14, `NamedTemporaryFile` gained `delete_on_close` (Windows-only,
defaults to `True`) to control whether the OS file handle that keeps the
file open also holds the delete-on-close flag. `TemporaryDirectory`
gained the `onexc` callback parameter as the replacement for the
deprecated `onerror` parameter.

### `_RandomNameSequence` and name generation (lines 61 to 140)

```python
class _RandomNameSequence:
    """An instance of _RandomNameSequence generates an endless
    sequence of unpredictable strings which can safely be incorporated
    into file names.  Each string is eight characters long.  Multiple
    threads can safely use the same instance at the same time.
    """
    characters = "abcdefghijklmnopqrstuvwxyz0123456789_"

    @property
    def rng(self):
        cur_pid = _os.getpid()
        if cur_pid != getattr(self, '_rng_pid', None):
            self._rng = _Random()
            self._rng_pid = cur_pid
        return self._rng

    def __iter__(self):
        return self

    def __next__(self):
        return ''.join(self.rng.choices(self.characters, k=8))
```

The `rng` property regenerates the `Random` instance when the PID
changes. This handles the fork case: without the PID check, both the
parent and the child process would share the same RNG state and could
generate colliding names. Note that `Random` is seeded from `os.urandom`
by default, so across-process collisions are already extremely unlikely,
but the PID guard makes it strictly impossible within one forked pair.

The `characters` alphabet deliberately omits uppercase letters and most
special characters so that the generated names are safe on
case-insensitive file systems and on file systems that restrict the
character set for filenames.

def mkstemp(suffix=None, prefix=None, dir=None, text=False):
    prefix, suffix, dir, output_type = _sanitize_params(prefix, suffix, dir)
    if text:
        flags = _text_openflags
    else:
        flags = _bin_openflags
    return _mkstemp_inner(dir, prefix, suffix, flags, output_type)

def _mkstemp_inner(dir, pre, suf, flags, output_type):
    names = _get_candidate_names()
    if output_type is bytes:
        dir = _os.fsencode(dir)
        pre = _os.fsencode(pre)
        suf = _os.fsencode(suf)
    for seq in range(TMP_MAX):
        name = next(names)
        file = _os.path.join(dir, pre + name + suf)
        _sys.audit("tempfile.mkstemp", file)
        try:
            fd = _os.open(file, flags, 0o600)
        except FileExistsError:
            continue
        except PermissionError:
            if (_os.name == 'nt' and _os.path.isdir(dir) and
                    _os.access(dir, _os.W_OK)):
                continue
            else:
                raise
        return (fd, _os.path.abspath(file))
    raise FileExistsError(_errno.EEXIST, "No usable temporary file name found")
```

`_mkstemp_inner` loops up to `TMP_MAX` (10000) times, generating a new
random name on each `FileExistsError`. The file is opened with `O_EXCL`
(included in `_bin_openflags`) so that the check-and-create is atomic at
the OS level. The descriptor is opened with permissions `0o600` so that
the creating process is the only one that can read or write the file
before the caller sets different permissions. `_sanitize_params` applies
the module-level `gettempdir()` and `gettempprefix()` defaults when the
caller passes `None`.

### `NamedTemporaryFile` and `_TemporaryFileWrapper` (lines 311 to 450)

class _TemporaryFileCloser:
    file = None
    close_called = False
    cleanup_called = False

    def cleanup(self, windows=False):
        if not self.cleanup_called:
            self.cleanup_called = True
            try:
                self.file.close()
            finally:
                if self.delete:
                    if windows and not self.delete_on_close:
                        self.unlink(self.name)
                    elif not windows:
                        self.unlink(self.name)

    def __del__(self):
        self.cleanup()

class _TemporaryFileWrapper:
    def __getattr__(self, name):
        # Attribute lookups are delegated to the underlying file
        # and cached for non-numeric results
        a = object.__getattribute__(self, '_file')
        a = getattr(a, name)
        if hasattr(a, '__call__'):
            func = a
            @_functools.wraps(func)
            def func_wrapper(*args, **kwargs):
                return func(*args, **kwargs)
            a = func_wrapper
        setattr(self, name, a)
        return a
```

`_TemporaryFileCloser` holds the actual cleanup logic. `__del__` ensures
the file is deleted even if the caller never calls `close()` or uses the
object as a context manager. The `cleanup_called` flag is checked before
each cleanup so that GC and explicit close do not race.

`_TemporaryFileWrapper` is the public object returned by
`NamedTemporaryFile`. It exposes `name` and `delete` as direct attributes
and delegates everything else to the wrapped file object via `__getattr__`.
The caching in `__getattr__` means frequently accessed attributes like
`read` and `write` are stored on the wrapper instance after the first
lookup, avoiding repeated delegation overhead.

### `SpooledTemporaryFile` spool-to-disk transition (lines 511 to 700)

<CpyLink path="Lib/tempfile.py" lines="511-700" />

```python
class SpooledTemporaryFile:
    def _check(self, file):
        if self._rolled:
            return
        max_size = self._max_size
        if max_size and file.tell() > max_size:
            self.rollover()

    def rollover(self):
        if self._rolled:
            return
        file = self._file
        newfile = self._file = TemporaryFile(**self._TemporaryFileArgs)
        newfile.write(file.getvalue())
        newfile.seek(file.tell(), 0)
        self._rolled = True

    def write(self, s):
        self._file.write(s)
        self._check(self._file)
```

`_check` is called after every write. When `_rolled` is `False` and the
in-memory buffer's position exceeds `max_size`, `rollover` is called.
`rollover` creates a real `TemporaryFile`, copies the buffer contents into
it, seeks to the same position the buffer was at, and sets `_rolled =
True`. All subsequent attribute lookups on the `SpooledTemporaryFile` fall
through to the real file because `__getattr__` checks `_rolled` and
delegates to `self._file` directly.

The `max_size=0` default means the file never spills to disk unless the
caller specifies a threshold, which makes `SpooledTemporaryFile()` behave
identically to an unbounded in-memory file. The threshold is compared
against `file.tell()` rather than `len(file.getvalue())` for efficiency:
`tell()` is O(1) on `BytesIO`/`StringIO`, while `getvalue()` copies the
buffer.
