## Reading

### Element: the core data structure

`Element` stores children in `_children`, a plain list. Iteration, slicing, `append`, `insert`, `extend`, and `remove` all delegate directly to `_children`. `text` holds character data before the first child; `tail` holds character data after the element's closing tag.

```python
# CPython: Lib/xml/etree/ElementTree.py:82 Element.__init__
class Element:
    tag = None
    attrib = None
    text = None
    tail = None

    def __init__(self, tag, attrib={}, **extra):
        if not callable(tag):
            tag = _coerce_tag(tag)
        self.tag = tag
        self.attrib = {**attrib, **extra}
        self._children = []
```

`Element.iter(tag)` performs a depth-first walk. `find`, `findall`, and `findtext` accept a limited XPath subset implemented in `ElementPath` (a sibling module in the same package).

### XMLParser and incremental feeding

`XMLParser` wraps `expat` and forwards SAX-style events to a `TreeBuilder`. `feed` is incremental; `close` finalizes parsing and returns the root element.

```python
# CPython: Lib/xml/etree/ElementTree.py:641 XMLParser.feed
class XMLParser:
    def __init__(self, *, target=None, encoding=None):
        self.parser = expat.ParserCreate(encoding, "}")
        if target is None:
            target = TreeBuilder()
        self.target = target
        ...
        self.parser.StartElementHandler = self._start
        self.parser.EndElementHandler = self._end
        self.parser.CharacterDataHandler = self._data

    def feed(self, data):
        """Feed encoded data to parser."""
        try:
            self.parser.Parse(data, False)
        except self._error as v:
            self._raiseerror(v)

    def close(self):
        """Finish feeding data to parser and return the root element."""
        try:
            self.parser.Parse(b"", True)
        except self._error as v:
            self._raiseerror(v)
        try:
            return self.target.close()
        finally:
            del self.parser, self.target
```

### iterparse: streaming large documents

`iterparse` is the standard idiom for processing large XML files without loading the full tree into memory. It wraps `XMLParser` with an event queue and yields `(event, elem)` pairs on demand.

```python
# CPython: Lib/xml/etree/ElementTree.py:721 iterparse (condensed)
for event, elem in iterparse("catalog.xml", events=("end",)):
    if elem.tag == "price":
        total += float(elem.text)
        elem.clear()   # drop children and text to keep memory flat
```

Calling `elem.clear()` inside the loop is the canonical idiom: it releases `_children`, `text`, `tail`, and `attrib` for elements that have already been processed.

### tostring and indent

`tostring` delegates to `ElementTree.write`, which calls `_serialize_xml` (or `_serialize_html` when `method="html"`). A `_namespaces` pre-pass collects all namespace URIs so `xmlns:` declarations appear on the root element rather than scattered through the tree.

```python
# CPython: Lib/xml/etree/ElementTree.py:861 tostring
def tostring(element, encoding="us-ascii", method="xml",
             *, xml_declaration=None, default_namespace=None,
             short_empty_elements=True):
    stream = io.BytesIO()
    ElementTree(element).write(
        stream, encoding, xml_declaration=xml_declaration,
        default_namespace=default_namespace, method=method,
        short_empty_elements=short_empty_elements)
    return stream.getvalue()
```

`indent` (added in 3.9) walks the tree and inserts or updates `text` and `tail` on each element to achieve indented output. It does not change the logical content; it only adds whitespace nodes.

## gopy notes

- The planned location is `module/xml_etree/` under gopy's flat module layout.
- Suggested port order: `Element` struct with slice-backed `_children`, then `TreeBuilder` using Go's `encoding/xml` as the expat replacement, then `XMLParser` wrapping `TreeBuilder`, then `parse`/`fromstring`/`tostring`, then `iterparse` using a goroutine-plus-channel pattern, then `indent` and `canonicalize` last.
- `_elementtree` (the C accelerator) is out of scope for gopy; the pure-Python path is the port target.
- `ElementPath` (the XPath subset) is a separate file (`Lib/xml/etree/ElementPath.py`) and must be ported alongside `ElementTree` for `find`/`findall` to work.

## CPython 3.14 changes

- `iterparse` now has a `__del__` finalizer that closes the underlying file object when iteration stops early, fixing a resource leak present since the class was introduced.
- `tostring` and `ElementTree.write` gained a `short_empty_elements` keyword argument (default `True`) controlling whether childless elements serialize as self-closing tags.
- `indent` gained a `level` parameter to start indentation at a depth other than zero, useful when inserting a subtree into an already-indented document.
- `C14NWriterTarget` now correctly handles `with_comments` for comment nodes that appear before the document element; this was previously silently ignored.
