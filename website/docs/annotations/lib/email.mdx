# `Lib/email/__init__.py`

<CpyLink path="Lib/email/__init__.py" />

`Lib/email/__init__.py` is a short entry-point (~79 lines) that exposes
four top-level convenience functions: `message_from_string`,
`message_from_bytes`, `message_from_binary_file`, and `message_from_file`.
Each one constructs a `Parser` or `BytesParser`, calls its `parse`/`parsestr`
method, and returns the resulting `Message` (or `EmailMessage`) object.

The real substance of the `email` package is distributed across a dozen
files. This page covers the `__init__.py` entry-point and then walks the
key submodules in the order a typical call chain exercises them: policy
selection, parsing, the message object, generation, MIME subclasses,
header encoding, and utility helpers.

The policy object is the central configuration knob. Every parser,
generator, and message object receives a policy at construction time.
`compat32` (the default) preserves the 2.x/3.x legacy behavior.
`EmailPolicy` (and its ready-made instances `email.policy.default`,
`email.policy.SMTP`, `email.policy.SMTPUTF8`, `email.policy.HTTP`)
enables the modern API: `EmailMessage` instead of `Message`, strict
header parsing, and Unicode-native output.

### Top-level convenience functions (lines 31 to 79)

<CpyLink path="Lib/email/__init__.py" lines="31-79" />

```python
def message_from_string(s, _class=Message, *, policy=compat32):
    from email.parser import Parser
    return Parser(_class, policy=policy).parsestr(s)

def message_from_bytes(s, _class=Message, *, policy=compat32):
    from email.parser import BytesParser
    return BytesParser(_class, policy=policy).parsebytes(s)

def message_from_file(fp, _class=Message, *, policy=compat32):
    from email.parser import Parser
    return Parser(_class, policy=policy).parse(fp)

def message_from_binary_file(fp, _class=Message, *, policy=compat32):
    from email.parser import BytesParser
    return BytesParser(_class, policy=policy).parse(fp)
```

Each function accepts an optional `_class` argument to substitute a
different message class (e.g., `EmailMessage`) and a `policy` keyword.
The deferred `import` inside each function avoids circular-import issues
at package load time, since `email.parser` in turn imports `email.message`.
Passing `policy=email.policy.default` to any of these functions switches
the returned object from the legacy `Message` to `EmailMessage` and
enables strict RFC 5322 parsing throughout.

### `FeedParser` state machine (Lib/email/feedparser.py)

```python
class FeedParser:
    def __init__(self, _factory=None, *, policy=compat32):
        self.policy = policy
        self._factory = _factory or policy.message_factory
        self._input = BufferedSubFile()
        self._msgstack = []
        self._parse = self._parsegen().__next__
        self._cur = self._factory()
        self._last = self._cur
        self._headersonly = False

    def feed(self, data):
        self._input.push(data)
        self._call_parse()

    def _parsegen(self):
        # yield-based coroutine; each yield suspends until more data arrives
        for line in self._input:
            if self._headersonly:
                lines = [line]
                for line in self._input:
                    lines.append(line)
                self._cur.set_payload(EMPTYSTRING.join(lines))
                return
            ...
            # header parsing, multipart boundary detection, etc.
```

`FeedParser` uses a generator-based coroutine to implement incremental
parsing. `_parsegen` is a generator; `_call_parse` advances it one step
by calling `next` on it. `BufferedSubFile` acts as a queue of lines that
`_parsegen` iterates over. This design means `feed(data)` can be called
multiple times with partial data (e.g., streaming a large email from a
network socket) and the parser will resume exactly where it suspended.
`BytesFeedParser` subclasses `FeedParser` and decodes each line through
the policy's `header_source_parse` method before handing it to the same
generator.

### `Message` header access and `walk` (Lib/email/message.py)

<CpyLink path="Lib/email/message.py" lines="1-900" />

```python
class Message:
    def __init__(self, policy=compat32):
        self._headers = []   # list of (name, value) pairs; preserves order
        self._payload = None
        self._charset = None
        self.policy = policy

    def __getitem__(self, name):
        return self.get(name)

    def get(self, name, failobj=None):
        name = name.lower()
        for k, v in self._headers:
            if k.lower() == name:
                return self.policy.header_fetch_parse(k, v)
        return failobj

    def walk(self):
        yield self
        if self.is_multipart():
            for subpart in self.get_payload():
                yield from subpart.walk()
```

`Message._headers` is a plain list of `(name, value)` 2-tuples rather
than a dict, which preserves duplicate headers (common for `Received:`,
`DKIM-Signature:`, etc.) and the original insertion order. Header lookups
are therefore O(n) in the number of headers, which is acceptable because
typical messages have at most a few dozen headers. `policy.header_fetch_parse`
allows the policy to decode RFC 2047 encoded words or return a structured
header object, depending on whether `compat32` or `EmailPolicy` is in use.
`walk` is a pre-order traversal of the MIME tree: it yields the message
itself, then recursively yields every sub-part. It is the standard way to
iterate all parts of a multipart message when processing attachments.

```python
def parsedate_to_datetime(data):
    *dtuple, tz = _parsedate_tz(data)
    if tz is None:
        return datetime.datetime(*dtuple[:6])
    return datetime.datetime(*dtuple[:6],
        tzinfo=datetime.timezone(datetime.timedelta(seconds=tz)))
```

`parseaddr` delegates to the `_AddressList` class from `email._parseaddr`,
which implements the RFC 2822 address grammar. It returns a `(realname, addr_spec)`
pair; if parsing fails it returns `('', '')` rather than raising. `formataddr`
takes the same pair and reassembles it: if the display name contains RFC 2822
specials (parentheses, angle brackets, commas, etc.) it wraps the name in
double quotes; if the name is non-ASCII it RFC 2047-encodes it using the
supplied charset. `parsedate_to_datetime` is the modern replacement for
`parsedate` and `parsedate_tz`: it always returns a `datetime.datetime`.
When the parsed date includes a timezone offset it attaches a
`datetime.timezone` with the correct UTC offset; otherwise it returns a
naive `datetime`.
