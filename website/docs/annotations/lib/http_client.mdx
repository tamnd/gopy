# `Lib/http/client.py`

<CpyLink path="Lib/http/client.py" />

`http/client.py` implements the client side of HTTP/1.1. It is the
backbone of `urllib.request` and most third-party HTTP libraries that
build on the standard library. The two main classes are `HTTPConnection`
(plain TCP) and `HTTPSConnection` (TLS wrapper), both sharing the same
request/response machinery.

An `HTTPConnection` models a single persistent connection to one
`(host, port)` pair. The caller sends one or more requests with
`request(method, url, body, headers)` and reads each response with
`getresponse()`. The connection is reused automatically for subsequent
requests unless the server sends `Connection: close` or an error forces
a reconnect.

`HTTPResponse` is the object returned by `getresponse()`. It exposes
`.status` (integer status code), `.reason` (reason phrase), `.headers`
(an `HTTPMessage` instance), and file-like read methods: `.read(amt)`,
`.readline()`, `.readinto(buf)`. It handles both identity-encoded and
chunked transfer-encoded bodies transparently.

The send path flows through `request` -> `_send_request` ->
`_send_output` -> `send`. The read path flows through `getresponse` ->
`HTTPResponse.begin` -> `_read_status` and then `read`/`_read_chunked`
on demand.

`begin` consumes the status line and headers from the raw socket file
object `self.fp`. It loops to absorb any `100 Continue` responses that
an upload might have triggered before the real response arrives.
`_read_status` enforces `_MAXLINE = 65536` on every `readline` call to
prevent a malicious server from exhausting memory with a never-ending
status line. The response version string (`HTTP/1.0` or `HTTP/1.1`) sets
`self.will_close`, which controls whether the connection is reused after
this response.

```python
def _read_chunked(self, amt):
    assert self.chunked != _UNKNOWN
    value = []
    try:
        while True:
            if self.chunk_left == 0:
                # read next chunk size
                line = self.fp.readline(_MAXLINE + 1)
                i = line.find(b";")
                if i >= 0:
                    line = line[:i]  # strip chunk extensions
                chunk_left = int(line, 16)
                if chunk_left == 0:
                    break
                self.chunk_left = chunk_left
            if amt is None:
                value.append(self._safe_read(self.chunk_left))
                self.chunk_left = 0
            elif amt < self.chunk_left:
                value.append(self._safe_read(amt))
                self.chunk_left -= amt
                break
            ...
    finally:
        ...
    # read trailing CRLF and optional trailers
    self._read_and_discard_trailer()
    ...
    return b"".join(value)
```

Chunked transfer encoding sends each body segment prefixed with its
length in hexadecimal. `_read_chunked` maintains `self.chunk_left` so
that partial `read(amt)` calls can resume mid-chunk without re-parsing
the size line. Chunk extensions (everything after the `;` on the size
line) are discarded. After the terminal zero-length chunk, `_read_and_discard_trailer`
consumes any trailer headers up to the blank line, preserving HTTP/1.1
compliance even though CPython's client does not expose trailer values.

```python
def _send_output(self, message_body=None, encode_chunked=False):
    self._buffer.extend((b"\r\n",))
    msg = b"".join(self._buffer)
    del self._buffer[:]
    self.send(msg)
    if message_body is not None:
        self.send(message_body)
```

`request` is the high-level entry point. It delegates to `_send_request`,
which decides between `Content-Length` (known-length body) and
`Transfer-Encoding: chunked` (file-like or generator body). For chunked
bodies, `endheaders` iterates the source in `blocksize`-sized pieces and
wraps each piece in its hex-length prefix. `_send_output` flushes the
header buffer accumulated by `putrequest`/`putheader` calls in a single
`send` syscall to minimize round trips, then sends the body separately.


`HTTPSConnection` inherits the entire request/response machinery from
`HTTPConnection` and only overrides `connect`. After the TCP handshake,
it calls `SSLContext.wrap_socket` with `server_hostname` set for SNI.
If a `set_tunnel` proxy was configured, `server_hostname` is the
ultimate destination host (the tunnel target), not the proxy, so that
the certificate is validated against the correct name. The default
context (`ssl._create_default_https_context`) enables certificate
verification and hostname checking unless the caller overrides them.
