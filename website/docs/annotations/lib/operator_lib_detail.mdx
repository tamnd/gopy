`operator.py` is the pure-Python reference implementation of the `operator` module. At runtime the C extension `_operator` replaces most of it via `from _operator import *` near the bottom of the file. What remains as non-replaceable Python are the dunder-name aliases (`__add__ = add`, etc.) assigned after the import, plus the class bodies of `attrgetter`, `itemgetter`, and `methodcaller`, which the C version mirrors exactly in structure.

## Reading

### truth, not_, is_, is_not

These look trivial but serve a real purpose: they turn operators into first-class callables that are picklable by name.

```python
# CPython: Lib/operator.py:57 truth
def truth(a):
    "Return True if a is true, False otherwise."
    return True if a else False

# CPython: Lib/operator.py:61 is_
def is_(a, b):
    "Same as a is b."
    return a is b
```

`truth` is not the same as `bool`: it always returns a plain `bool` literal, never a `bool` subclass instance. `is_` / `is_not` wrap the identity operators so they can be passed to `filter`, `map`, or `sorted` as the key.

### matmul and imatmul (PEP 465)

`matmul` and its in-place form `imatmul` were added in Python 3.5 (PEP 465) for matrix multiplication. They are ordinary functions in the pure-Python fallback.

```python
# CPython: Lib/operator.py:116 matmul
def matmul(a, b):
    "Same as a @ b."
    return a @ b

# CPython: Lib/operator.py:385 imatmul
def imatmul(a, b):
    "Same as a @= b."
    a @= b
    return a
```

The `__matmul__ = matmul` alias at line 448 ensures that `pickle` can round-trip `operator.matmul` objects even when the C extension has replaced the function.

### length_hint

`length_hint` implements the `__length_hint__` protocol (PEP 424). It tries `len()` first for exact counts, then falls back to `type(obj).__length_hint__`.

```python
# CPython: Lib/operator.py:193 length_hint
def length_hint(obj, default=0):
    if not isinstance(default, int):
        raise TypeError(...)
    try:
        return len(obj)
    except TypeError:
        pass
    try:
        hint = type(obj).__length_hint__
    except AttributeError:
        return default
    try:
        val = hint(obj)
    except TypeError:
        return default
    if val is NotImplemented:
        return default
    if not isinstance(val, int):
        raise TypeError(...)
    if val < 0:
        raise ValueError(...)
    return val
```

Looking up `__length_hint__` on `type(obj)` rather than `obj` is intentional: it follows the descriptor protocol and avoids accidentally calling an instance attribute that happens to have the same name.

### attrgetter, itemgetter, methodcaller

All three are Python classes whose `__reduce__` methods make them picklable. The constructor builds a closure stored in `self._call` so that `__call__` is a single function pointer dereference.

```python
# CPython: Lib/operator.py:250 attrgetter.__init__ single-attr path
def __init__(self, attr, /, *attrs):
    if not attrs:
        if not isinstance(attr, str):
            raise TypeError('attribute name must be a string')
        self._attrs = (attr,)
        names = attr.split('.')
        def func(obj):
            for name in names:
                obj = getattr(obj, name)
            return obj
        self._call = func
```

Dotted paths such as `attrgetter('a.b.c')` split on `'.'` and chain `getattr` calls in a loop, not recursion. The multi-attr variant wraps several single-attr getters and returns a tuple.

`methodcaller.__reduce__` has a special case: if `kwargs` are present it cannot pickle as `(class, (name,) + args)` because `**kwargs` is not representable that way, so it uses `functools.partial` to bind the keyword arguments:

```python
# CPython: Lib/operator.py:337 methodcaller.__reduce__
def __reduce__(self):
    if not self._kwargs:
        return self.__class__, (self._name,) + self._args
    else:
        from functools import partial
        return partial(self.__class__, self._name, **self._kwargs), self._args
```

### Dunder aliases for pickling

After `from _operator import *` replaces the module-level functions with their C equivalents, the file reassigns every function to a dunder name:

```python
# CPython: Lib/operator.py:430 dunder alias block (excerpt)
__lt__ = lt
__le__ = le
__eq__ = eq
__add__ = add
__matmul__ = matmul
# ... etc.
```

This matters for `pickle`: the default pickle protocol records the module-level name of a function. `pickle.dumps(operator.add)` serialises as `operator.add`; `pickle.dumps(operator.__add__)` would serialise as `operator.__add__`. Both survive a round-trip because both names exist in the module's namespace after this block runs.

## gopy notes

- The pure-Python `attrgetter`, `itemgetter`, and `methodcaller` classes need Go ports with the same `__reduce__` behaviour to support `pickle` of operator objects.
- `length_hint` is used by CPython's list and bytearray constructors to pre-allocate capacity; gopy should route the same call in `objects/list.go` and `objects/bytes.go`.
- `truth` shows up as the fallback for `bool()` on objects without `__bool__` or `__len__`; gopy already handles this in `objects/type_call.go` but the module-level alias must exist.
- `matmul`/`imatmul` require the `BINARY_OP`/`BINARY_OP_INPLACE` dispatch in `vm/eval_gen.go` to route `@` and `@=` correctly.
- The dunder-alias block at 430–475 must execute after `_operator` is imported, or the aliases would point at the pure-Python stubs. In gopy the module initialiser must preserve this ordering.

## CPython 3.14 changes

- `is_none` and `is_not_none` were added as convenience predicates (lines 69–75); they were not present in 3.12.
- `call` (line 234) was added in 3.11 to make `obj(...)` expressible as a first-class operator.
- The `__all__` list at lines 13–20 was updated to include `call`, `is_none`, and `is_not_none`.
- No changes to the core arithmetic or comparison functions; the C extension remains the primary implementation path.
