# `Lib/html/parser.py`

<CpyLink path="Lib/html/parser.py" />

`html.parser` is a pure-Python push parser. Unlike `xml.etree.ElementTree`
it does not build an in-memory tree; instead it invokes a set of
`handle_*` callbacks as it recognises tokens. Subclasses override the
callbacks they care about and ignore the rest.

The parser inherits from `_markupbase.ParserBase`, which handles
`<!DOCTYPE ...>` declarations, marked sections (`<![CDATA[ ... ]]>` and
`<![INCLUDE[ ... ]]>`), and the line/column position tracking used in
error messages.

`HTMLParser` accepts malformed HTML. The `goahead` scan loop is driven by
a set of compiled regexes (`starttagfind`, `endtagfind`, `charref`,
`entityref`, etc.). When a token boundary cannot be found the parser
buffers remaining data and waits for the next `feed` call.

The `convert_charrefs` flag (default `True` since 3.5) causes all
character references in text and attribute values to be converted to the
corresponding Unicode characters before the handle callback is invoked.
When the flag is `False`, `handle_entityref` and `handle_charref` are
called separately for each reference.

`goahead` is the central loop. When `convert_charrefs` is `True` it
searches for the next `<` directly, delivers the intervening text as a
single `handle_data` call, and then dispatches on the tag type. When
`convert_charrefs` is `False` it uses the `interesting` regex (which also
matches `&`) so that entity references trigger separate callbacks. The
`end` argument is `0` during incremental `feed` calls (allow partial
tokens to remain buffered) and `1` during `close` (flush everything).

`attrfind_tolerant` is a lenient regex that handles unquoted, single-quoted,
and double-quoted attribute values, as well as valueless boolean attributes.
Attribute names are lower-cased unconditionally to match the HTML spec.
`unescape` is called on each attribute value after stripping quotes so that
references like `href="&amp;q=1"` reach the callback as `&q=1`. Void
elements (`<br/>`, `<img/>`) trigger `handle_startendtag` instead of a
separate `handle_starttag` + `handle_endtag` pair.

`unescape` is a module-level function (not a method) so it can be used

```python
def handle_comment_token(self, i):
    rawdata = self.rawdata
    j = rawdata.find('-->', i+4)
    if j < 0:
        return -1  # incomplete
    self.handle_comment(rawdata[i+4:j])
    return j + 3

def goahead_pi(self, i):
    rawdata = self.rawdata
    j = rawdata.find('?>', i+2)
    if j < 0:
        return -1
    self.handle_pi(rawdata[i+2:j])
    return j + 2
```

Comments (`<!-- ... -->`), processing instructions (`<?target data?>`),
and declarations (`<!...>`) are each handled by a dedicated scanner that
searches for the appropriate closing delimiter. All three return `-1` when
the delimiter is not yet in the buffer, leaving the unconsumed data in
`rawdata` for the next `feed` call. The `_markupbase.ParserBase.handle_decl`
override specifically recognises `DOCTYPE` and delegates the internal
subset to `goahead_markupdecl`.
