# `Include/internal/pycore_long.h`

<CpyLink path="Include/internal/pycore_long.h" />

Exposes the compact-integer internal layout to C files inside the
interpreter that need to read or manipulate integer bits without going
through the public `PyLong_AsLong()` path. Extension authors never
include this directly; it is consumed by `Objects/longobject.c`,
the specializing adaptive interpreter in `Python/specialize.c`, and
the compile-time constant folding pass.

The central idea is the "compact integer" representation introduced
in CPython 3.12. A `PyLongObject` whose absolute value fits in a
single 30-bit digit stores that digit inline in the `lv_tag` word
rather than in a heap-allocated digits array. The `lv_tag` field's
low two bits encode the sign (0 = positive, 2 = negative, 1 = zero
tag), and the upper bits encode the digit count. For compact integers
the digit count is exactly 1 and the value sits in the first (and
only) element of `long_value.ob_digit`.

This layout lets the `BINARY_OP_ADD_INT` specialized opcode add two
small integers with a handful of register operations, completely
bypassing the general `_PyLong_Add` path.

### `lv_tag` encoding (lines 93 to 105)

<CpyLink path="Include/internal/pycore_long.h" lines="93-105" />

```c
/* Bottom two bits of lv_tag encode sign. */
#define _PyLong_SIGN_MASK       3
#define _PyLong_TAG_ZERO        1   /* the integer 0 */
#define _PyLong_TAG_POSITIVE    0
#define _PyLong_TAG_NEGATIVE    2

/* Upper bits encode the number of digits. */
#define _PyLong_NOF_DIGITS_SHIFT 2

/* Reconstruct the digit count from lv_tag. */
static inline Py_ssize_t
_PyLong_DigitCount(const PyLongObject *op) {
    return (Py_ssize_t)(op->long_value.lv_tag >> _PyLong_NOF_DIGITS_SHIFT);
}
```

The `lv_tag` word packs two pieces of information so that the
common predicate "is this a compact positive integer?" compiles to a
single compare-and-mask. Bit 0 and bit 1 hold the sign tag: 0 means
positive (non-zero), 1 means the special zero value, and 2 means
negative. The remaining upper bits store the digit count, which for a
compact integer is always 1.

Zero is a special case: it has sign tag 1 and digit count 0, so
`lv_tag == 1`. The identity predicate `_PyLong_IsZero` exploits this
by checking `lv_tag == 1` directly rather than extracting a value.

In gopy, `objects/long.go` mirrors this with `lvTag uint` and the same
three constant values (`lvTagZero`, `lvTagPositive`, `lvTagNegative`).
The digit count is extracted via `lvTag >> 2`.

### `_PyLong_IsCompact` and `_PyLong_CompactValue` (lines 1 to 38)

<CpyLink path="Include/internal/pycore_long.h" lines="1-38" />

```c
static inline bool
_PyLong_IsCompact(const PyLongObject *op) {
    assert(PyLong_Check(op));
    return op->long_value.lv_tag < (2 << _PyLong_NOF_DIGITS_SHIFT);
}

static inline Py_ssize_t
_PyLong_CompactValue(const PyLongObject *op) {
    assert(_PyLong_IsCompact(op));
    Py_ssize_t sign = 1 - (op->long_value.lv_tag & _PyLong_SIGN_MASK);
    return sign * (Py_ssize_t)op->long_value.ob_digit[0];
}
```

`_PyLong_IsCompact` tests whether the digit count encoded in
`lv_tag >> 2` is 0 or 1. Digit count 0 means the integer is zero;
digit count 1 means the value fits in one 30-bit digit. Both cases
are "compact" because the value is directly accessible without
iterating a multi-digit array.

`_PyLong_CompactValue` converts the sign tag to `+1` or `-1` using
`1 - tag`. For the zero tag (`tag == 1`), `sign` evaluates to `0`,
which multiplies `ob_digit[0]` to zero regardless of its content.
For a positive tag (`tag == 0`), `sign == 1` and the raw digit is
returned. For a negative tag (`tag == 2`), `sign == -1` and the value
is negated.

The function is explicitly documented as undefined behaviour when
called on a non-compact object, so callers must always guard with
`_PyLong_IsCompact` first.

In gopy, `objects/long.go` provides `IsCompact() bool` and
`CompactValue() int` with the same contract. The Go implementation
uses a `panic` rather than UB for the non-compact guard violation.

### Identity predicates (lines 53 to 65)

<CpyLink path="Include/internal/pycore_long.h" lines="53-65" />

```c
static inline bool _PyLong_IsZero(const PyLongObject *op) {
    return op->long_value.lv_tag == _PyLong_TAG_ZERO;
}
static inline bool _PyLong_IsOne(const PyLongObject *op) {
    return (op->long_value.lv_tag == _PyLong_TAG_POSITIVE) &&
           (op->long_value.ob_digit[0] == 1);
}
static inline bool _PyLong_IsMinusOne(const PyLongObject *op) {
    return (op->long_value.lv_tag == _PyLong_TAG_NEGATIVE) &&
           (op->long_value.ob_digit[0] == 1);
}
```

These three predicates are used throughout the interpreter and
standard library as cheap guards before heavier operations. For
example, `PyNumber_Multiply` checks `_PyLong_IsOne` before allocating
a result object, and `PyNumber_Power` checks `_PyLong_IsZero` to short
circuit the entire exponentiation.

All three predicates work on both compact and non-compact objects
because they test `lv_tag` directly: a non-compact integer with tag 0
has at least 2 digits and so its `ob_digit[0]` can never equal 1 with
the expected tag. No separate compactness check is required.

### `_PyLong_BothAreCompact` and fast arithmetic (lines 66 to 92)

<CpyLink path="Include/internal/pycore_long.h" lines="66-92" />

```c
static inline bool
_PyLong_BothAreCompact(const PyLongObject *a, const PyLongObject *b) {
    return (a->long_value.lv_tag | b->long_value.lv_tag)
               < (2 << _PyLong_NOF_DIGITS_SHIFT);
}

PyAPI_FUNC(PyObject *) _PyLong_FastAdd(
    PyLongObject *left, PyLongObject *right);
PyAPI_FUNC(PyObject *) _PyLong_FastSub(
    PyLongObject *left, PyLongObject *right);
```

`_PyLong_BothAreCompact` ORs the two tag words together before the
single range check. If either operand has a digit count greater than 1
the OR will set a bit above position 3, making the combined value
exceed the threshold. This lets the compiler emit a single branch for
the two-operand check with no short-circuit overhead.

`_PyLong_FastAdd` and `_PyLong_FastSub` are called from the
`BINARY_OP_ADD_INT` and `BINARY_OP_SUBTRACT_INT` specialized opcodes
after `_PyLong_BothAreCompact` succeeds. They perform the arithmetic
in `Py_ssize_t`, check for overflow, and only fall back to
`_PyLong_Add` when the result would exceed the compact range. The
common path allocates no memory: both CPython's small integer cache
and gopy's interning layer can often return an existing object.

In gopy, `objects/long.go` exports `FastAdd(a, b *Long) *Long` and
`FastSub(a, b *Long) *Long` with overflow detection using
`bits.Add` / `bits.Sub` from the standard library.
