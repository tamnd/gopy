# `Python/dtoa.c`

<CpyLink path="Python/dtoa.c" />

David M. Gay's `dtoa` and `strtod` routines, downloaded from
`http://www.netlib.org/fp/dtoa.c` and modified for CPython by Mark
Dickinson and Eric Smith. The file provides correctly-rounded
conversions between decimal strings and IEEE 754 double-precision
values. "Correctly rounded" means the result is the nearest
representable `double`, with ties broken by the round-even rule,
matching what the IEEE 754 standard requires.

The entire body is guarded by `#if _PY_SHORT_FLOAT_REPR == 1`
(lines 129 to 2804). On platforms where short float repr is
disabled the three public symbols are still declared (as stubs) but
the multi-precision machinery is omitted.

The internal workhorse is the `Bigint` type: a sign-magnitude
arbitrary-precision integer stored as an array of `uint32_t` words.
`Bigint` instances are drawn from per-interpreter pool allocators
(`Balloc` / `Bfree`), keyed by the number of words needed, to avoid
malloc overhead during the tight conversion loop. In 3.14 the pool
array lives in `interp->dtoa` and is initialised at interpreter
startup by `_PyDtoa_Init`.

`_Py_dg_strtod` (lines 1386 to 2108) is the slow but exact path
called from `PyOS_string_to_double` when the fast `strtod`
approximation is not provably correct. `_Py_dg_dtoa` (lines 2195 to
2801) is called from `PyOS_double_to_string` for the shortest-repr
and fixed-precision modes.

gopy delegates both directions to Go's `strconv.ParseFloat` and
`strconv.FormatFloat`, which give the same IEEE 754 guarantees on all
supported platforms, so the `Bigint` machinery has no Go equivalent.

### `Bigint` memory pool (lines 341 to 441)

```c
static Bigint *
Balloc(int k)
{
    int x;
    Bigint *rv;
    unsigned int len;

    PyInterpreterState *interp = _PyInterpreterState_GET();
    Bigint **p5s = interp->dtoa.freelist;
    if (k <= Kmax && (rv = p5s[k]) != NULL) {
        p5s[k] = rv->next;
    }
    else {
        x = 1 << k;
        len = (sizeof(Bigint) + (x-1)*sizeof(ULong) + sizeof(double) - 1)
                /sizeof(double);
        rv = (Bigint*) PyMem_Malloc(len*sizeof(double));
        if (rv == NULL)
            return NULL;
        rv->k = k;
        rv->maxwds = x;
    }
    rv->sign = rv->wds = 0;
    return rv;
}
```

The pool design keeps allocation out of the hot path. `k` is the
size class: pool `k` holds `Bigint`s with `maxwds == 2**k`. The
interpreter-local freelist means no locking is needed in the GIL
build. When `Py_GIL_DISABLED` or `Py_USING_MEMORY_DEBUGGER` is
set the alternate `Balloc` at line 403 bypasses the pool entirely
and calls `PyMem_Malloc` directly, accepting the overhead in exchange
for cleaner memory tracking.

### `ulp` and `b2d` — the binary ↔ Bigint bridge (lines 909 to 978)

<CpyLink path="Python/dtoa.c" lines="909-978" />

```c
static double
ulp(U *x)
{
    Long L;
    U u;
    L = (word0(x) & Exp_mask) - (P-1)*Exp_msk1;
    word0(&u) = L;
    word1(&u) = 0;
    return dval(&u);
}

static double
b2d(Bigint *a, int *e)
{
    ULong *xa, *xa0, w, y, z;
    int k;
    U d;

    xa0 = a->x;
    xa = xa0 + a->wds;
    y = *--xa;
    k = hi0bits(y);
    *e = 32 - k;
    if (k < Ebits) {
        word0(&d) = Exp_1 | y >> (Ebits - k);
        w = xa > xa0 ? *--xa : 0;
        word1(&d) = y << ((32-Ebits) + k) | w >> (Ebits - k);
        goto ret_d;
    }
    ...
    return dval(&d);
}
```

`ulp` reads the exponent field of a `double` directly through the
`U` union and returns `2**(exp - 52)`, the spacing between adjacent
representable values. `b2d` packs the most significant bits of a
`Bigint` into a `double` mantissa and returns the binary exponent
`e` such that `b * 2**e` equals the full integer. Together they let
`_Py_dg_strtod` compare the magnitude of the rounding error against
the size of a ulp without doing exact `Bigint` arithmetic.

The fast path handles the common case: if the input has at most
`DBL_DIG+1` significant digits and the exponent is small, a
straight multiply by a pre-computed power of ten gives an exact
result. The slow path (the `for (;;)` loop) builds `Bigint`

estimate.
