`Python/errors.c` owns every entry point for setting, querying, clearing, and normalising the per-thread exception state. Since 3.12 the three-field `exc_type/exc_value/exc_traceback` triplet was collapsed into a single `tstate->current_exception` object.

## Reading

### Setting an exception

`PyErr_SetObject` is the canonical setter. It constructs the new exception value if needed and stores it on the thread state.

```c
// CPython: Python/errors.c:49 PyErr_SetObject
void
PyErr_SetObject(PyObject *exception, PyObject *value)
{
    PyThreadState *tstate = _PyThreadState_GET();
    Py_XDECREF(tstate->current_exception);
    Py_XINCREF(value);
    tstate->current_exception = value;
}
```

The single-field design (post-3.12) means there is no longer a separate `exc_type` or `exc_traceback` slot. Those are now attributes on the exception instance itself.

### Legacy fetch/restore pair

Code predating 3.12 called `PyErr_Fetch` to pop the triplet and `PyErr_Restore` to push it back. Both shims survive in 3.14 for C-extension compatibility.

```c
// CPython: Python/errors.c:291 PyErr_Fetch
void
PyErr_Fetch(PyObject **p_type, PyObject **p_value, PyObject **p_traceback)
{
    PyThreadState *tstate = _PyThreadState_GET();
    _PyErr_StackItem *exc_info = tstate->exc_info;
    *p_value     = exc_info->exc_value;
    *p_type      = *p_value ? (PyObject *)Py_TYPE(*p_value) : NULL;
    *p_traceback = *p_value ? PyException_GetTraceback(*p_value) : NULL;
    exc_info->exc_value = NULL;
}
```

### Normalisation

`PyErr_NormalizeException` is called whenever an exception escapes a `try` block. If `*val` is a class rather than an instance, the function calls it with no arguments.

```c
// CPython: Python/errors.c:390 PyErr_NormalizeException
void
PyErr_NormalizeException(PyObject **exc, PyObject **val, PyObject **tb)
{
    if (*val == NULL || PyExceptionInstance_Check(*val))
        return;
    PyObject *type = *exc;
    PyObject *value = PyObject_CallOneArg(type, *val);
    if (value == NULL) { return; }
    Py_DECREF(*val);
    *val = value;
}
```

### Exception matching

`PyErr_GivenExceptionMatches` implements the `except Foo:` check. For tuples it recurses; for single types it calls `PyObject_IsSubclass`.

```c
// CPython: Python/errors.c:493 PyErr_GivenExceptionMatches
int
PyErr_GivenExceptionMatches(PyObject *err, PyObject *exc)
{
    if (PyTuple_Check(exc)) {
        Py_ssize_t i, n = PyTuple_GET_SIZE(exc);
        for (i = 0; i < n; i++)
            if (PyErr_GivenExceptionMatches(err, PyTuple_GET_ITEM(exc, i)))
                return 1;
        return 0;
    }
    return PyObject_IsSubclass(err, exc);
}
```

## gopy notes

- `tstate->current_exception` maps to a single `PyObject` field on `PyThreadState`. In gopy this is `ThreadState.CurrentException *Object`.
- `PyErr_Fetch` / `PyErr_Restore` are emulated via getter/setter helpers. Do not model the legacy triplet as three separate fields.
- `_PyErr_ChainExceptions` sets `__context__` unconditionally and `__cause__` only when `raise X from Y` is used. Both paths must be handled in `vm/eval_unwind.go`.
- `PyErr_NormalizeException` must run before any `except` clause check. In gopy this lives in `errors.Normalize`.

## CPython 3.14 changes

- The 3.12 single-slot migration is complete. `PyErr_Fetch` / `PyErr_Restore` are deprecated but not removed.
- `_PyErr_ChainExceptions1` was added as a one-argument variant accepting a single `exc_value`. The two-argument `_PyErr_ChainExceptions` is now a thin wrapper around it.
- `PyErr_SetRaisedException` was promoted to stable ABI in 3.12 and remains the preferred setter in 3.14.
