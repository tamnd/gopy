`symtable.c` is the compiler pass that walks the AST before bytecode generation
and answers the question: for every name in every block, is it local, global,
free (closed over from an enclosing scope), or a cell (captured by an inner
function)? The compiler in `Python/compile.c` reads the result to emit
`LOAD_FAST`, `LOAD_DEREF`, `LOAD_GLOBAL`, etc.

## Reading

### `symtable_add_def`

Every time the walker encounters a binding occurrence of a name it calls
`symtable_add_def` with one or more `DEF_*` flag bits. The function ORs the
new flags into the name's existing entry in the current block's `ste_symbols`
dict (a `long` stored as a Python int).

```c
// CPython: Python/symtable.c:368 symtable_add_def
static int
symtable_add_def(struct symtable *st, PyObject *name, int flag,
                 int lineno, int col_offset,
                 int end_lineno, int end_col_offset)
{
    PyObject *o;
    long val;
    /* ... look up name in ste_symbols ... */
    val = PyLong_AS_LONG(o);
    if ((flag & DEF_PARAM) && (val & DEF_PARAM)) {
        /* duplicate parameter */
        PyErr_Format(...);
        return 0;
    }
    val |= flag;
    /* store updated flags back */
}
```

Key flag constants (defined in `symtable.h`):

| Flag | Meaning |
|------|---------|
| `DEF_LOCAL` | name bound in this block |
| `DEF_GLOBAL_EXPLICIT` | `global` statement |
| `DEF_GLOBAL_IMPLICIT` | referenced at module scope |
| `DEF_PARAM` | function parameter |
| `DEF_IMPORT` | bound by an `import` statement |
| `DEF_FREE` | referenced but not bound here |
| `DEF_CELL` | captured by an inner function |

### `symtable_visit_stmt`

The recursive statement walker. Covers all AST statement node types. Entering a
`FunctionDef` or `ClassDef` node calls `symtable_enter_block`, which pushes a
new `PySTEntryObject` onto the block stack.

```c
// CPython: Python/symtable.c:512 symtable_visit_stmt
static int
symtable_visit_stmt(struct symtable *st, stmt_ty s)
{
    switch (s->kind) {
    case FunctionDef_kind:
        VISIT(st, expr, s->v.FunctionDef.args->defaults);
        if (!symtable_enter_block(st, s->v.FunctionDef.name, ...))
            return 0;
        VISIT_SEQ(st, stmt, s->v.FunctionDef.body);
        if (!symtable_exit_block(st))
            return 0;
        break;
    /* ... other cases ... */
    }
    return 1;
}
```

### `analyze_block`

The second pass over the block tree. After all `DEF_*` flags are set,
`analyze_block` recurses into child blocks and promotes names:

- A name that appears free in an inner block and is locally defined in an outer
  block becomes a `DEF_CELL` in the outer block.
- The inner block gets `DEF_FREE` for the same name, which causes the compiler
  to emit `LOAD_DEREF` rather than `LOAD_FAST`.

```c
// CPython: Python/symtable.c:1012 analyze_block
static int
analyze_block(PySTEntryObject *ste, PyObject *bound, PyObject *free,
              PyObject *global, PyObject *type_params, struct symtable *st)
{
    /* For each child scope, collect its free vars.
       Any free var that is bound in this scope becomes a cell. */
    if (!analyze_child_block(c, newbound, newfree, newglobal,
                             new_type_params, st))
        return 0;
    /* Merge newfree into cells for this block */
}
```

### `_PyST_GetScope`

Public query function used by `compile.c` to decide which opcode to emit.

```c
// CPython: Python/symtable.c:1432 _PyST_GetScope
int
_PyST_GetScope(PySTEntryObject *ste, PyObject *name)
{
    PyObject *v = PyDict_GetItemWithError(ste->ste_symbols, name);
    if (!v) return 0;
    long flags = PyLong_AS_LONG(v);
    return (flags >> SCOPE_OFFSET) & SCOPE_MASK;
}
```

Return values map to `LOCAL`, `GLOBAL_IMPLICIT`, `GLOBAL_EXPLICIT`, `FREE`,
`CELL`, or `0` (unknown / module-level global).

## gopy notes

gopy's symbol table lives in `compile/`. The pass runs between parsing and
`codegen_stmt.go`. Key alignment points:

- `DEF_*` flag constants in `compile/compiler.go` must match CPython's values
  because the flag integers are compared with bitwise ops, not by name.
- `analyze_block` logic is in `compile/flowgraph_passes.go`. The free-to-cell
  promotion loop must run bottom-up (inner blocks before outer) to match
  CPython's traversal order; reversing the order produces wrong `CELL` sets.
- `_PyST_GetScope` corresponds to the `scopeOf` helper in `compile/compiler.go`.
  The `SCOPE_OFFSET` shift must equal CPython's value (currently 11 bits).
- `symtable_visit_stmt` for comprehensions requires a synthetic function block
  (CPython creates an implicit function scope for `[x for x in ...]`). This is
  handled in `compile/codegen_expr_name.go`.

## CPython 3.14 changes

- 3.12: `LOAD_GLOBAL` became a two-word instruction; `symtable.c` gained a
  `DEF_GLOBAL_IMPLICIT` flag to distinguish unqualified module-level names from
  explicitly-declared `global` names so the compiler emits the right cache slot.
- 3.13: Type parameter scopes (`type X = ...`, PEP 695) introduced a new block
  kind `TypeParam_kind`; `analyze_block` gained the `type_params` argument to
  thread type-param free vars correctly.
- 3.14: `symtable_visit_expr` extended for PEP 701 f-string sub-expressions,
  which can now contain arbitrary expressions that must be analysed for closures.
