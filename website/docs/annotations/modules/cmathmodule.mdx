# `Modules/cmathmodule.c`

<CpyLink path="Modules/cmathmodule.c" />

`cmathmodule.c` is the C implementation of the `cmath` standard-library
module. Every function takes and returns `Py_complex`, the C struct
`{ double real; double imag; }`. No function operates on Python objects
internally beyond the argument-parsing and result-boxing boilerplate
generated by Argument Clinic.

The file groups naturally into four sections. The first covers the
elementary transcendentals: `sqrt`, `exp`, `log`, `sin`, `cos`, `tan` and
their inverses `asin`, `acos`, `atan`. The second covers the hyperbolic
group: `sinh`, `cosh`, `tanh`, `asinh`, `acosh`, `atanh`. The third covers
polar-form conversions: `phase`, `polar`, `rect`. The fourth covers the IEEE
predicates `isinf`, `isnan`, `isfinite`, and the PEP 485 approximation test
`isclose`.

Branch-cut semantics follow the C99 Annex G standard throughout. Notably,
`log`, `sqrt`, `asin`, and `acos` each have a branch cut on the negative
real axis, and `atan`, `atanh` each have one on the imaginary axis. CPython
documents these cuts explicitly because they differ from some CAS conventions.

### Special-value table and `SPECIAL_VALUE` macro (lines 1 to 60)

<CpyLink path="Modules/cmathmodule.c" lines="1-60" />

Many complex functions are undefined or return special values when one or
both components are NaN or infinity. Rather than scattering `if (isinf ||
isnan)` checks throughout each function, CPython defines a compact 3x3
lookup table and a macro that dispatches into it before the main
computation:

```c
#define SPECIAL_VALUE(z, table)                     \
    if (!Py_IS_FINITE((z).real) || !Py_IS_FINITE((z).imag)) { \
        r = table[special_type((z).real)]           \
                 [special_type((z).imag)];           \
        if (Py_IS_NAN(r.real) || Py_IS_NAN(r.imag)) \
            errno = EDOM;                            \
        return r;                                    \
    }

static int
special_type(double d)
{
    if (Py_IS_FINITE(d))   return ST_FINITE;
    if (Py_IS_INFINITY(d)) return (d > 0) ? ST_POS_INF : ST_NEG_INF;
    return ST_NAN;
}
```

`special_type` maps a `double` to one of four `ST_*` constants (`ST_FINITE`,
`ST_POS_INF`, `ST_NEG_INF`, `ST_NAN`). Each function that uses the macro
defines a `Py_complex` table with pre-computed results for the nine
non-finite combinations, following the C99 Annex G rules. If the selected
table entry has NaN components, `errno` is set to `EDOM` to signal a domain
error to the caller.

### `cmath_exp_impl` and `cmath_sqrt_impl` (lines 540 to 700)

<CpyLink path="Modules/cmathmodule.c" lines="540-700" />

`cmath_exp` uses Euler's formula: `exp(x + iy) = exp(x) * (cos(y) + i*sin(y))`.
The real and imaginary parts are computed separately to avoid the precision
loss that `cexp(3)` can introduce on some platforms:

```c
static Py_complex
cmath_exp_impl(PyObject *module, Py_complex z)
{
    Py_complex r;
    double l;

    SPECIAL_VALUE(z, exp_special_values);

    if (z.real > CM_LOG_LARGE_DOUBLE) {
        /* exp(real) would overflow: scale and adjust exponent */
        l = exp(z.real - 1.0);
        r.real = l * cos(z.imag) * M_E;
        r.imag = l * sin(z.imag) * M_E;
    } else {
        l = exp(z.real);
        r.real = l * cos(z.imag);
        r.imag = l * sin(z.imag);
    }
    if (Py_IS_INFINITY(r.real) || Py_IS_INFINITY(r.imag))
        errno = ERANGE;
    return r;
}
```

`cmath_sqrt` computes `sqrt(|z|) * exp(i * arg(z) / 2)` using the formula
`r.real = sqrt((|z| + |x|) / 2)`, `r.imag = y / (2 * r.real)`, which
avoids intermediate overflow and handles the negative-real-axis branch cut
by checking the sign of the imaginary part.

### Trig functions via product identity (lines 380 to 540)

<CpyLink path="Modules/cmathmodule.c" lines="380-540" />

All six trig and hyperbolic functions use the product-of-real-functions
identity. For example, `cmath_sin` expands `sin(x + iy)` as:

```c
static Py_complex
cmath_sin_impl(PyObject *module, Py_complex z)
{
    Py_complex r;

    SPECIAL_VALUE(z, sin_special_values);

    r.real = sin(z.real) * cosh(z.imag);
    r.imag = cos(z.real) * sinh(z.imag);
    return r;
}
```

`sin(x + iy) = sin(x)*cosh(y) + i*cos(x)*sinh(y)`. The analogous
expansions for `cos`, `tan`, `sinh`, `cosh`, and `tanh` follow the same
pattern. This explicit form avoids calling `csin(3)` from the system math
library, whose accuracy varies across platforms, in favour of the
well-tested scalar `sin`, `cos`, `sinh`, `cosh` from `<math.h>`.

### Polar-form helpers (lines 700 to 820)

<CpyLink path="Modules/cmathmodule.c" lines="700-820" />

`cmath_phase` returns `atan2(z.imag, z.real)` as a Python float. `cmath_polar`
builds a `(r, phi)` tuple:

```c
static PyObject *
cmath_polar_impl(PyObject *module, Py_complex z)
{
    double r, phi;
    r   = _Py_c_abs(z);            /* sqrt(real*real + imag*imag) */
    phi = atan2(z.imag, z.real);
    return PyTuple_Pack(2, PyFloat_FromDouble(r),
                           PyFloat_FromDouble(phi));
}
```

`cmath_rect(r, phi)` is the inverse: it constructs `r*(cos(phi)+i*sin(phi))`
while handling the special cases where `r` is zero (result is `0+0j`
regardless of `phi`) and where `phi` is infinity or NaN (result is NaN). This
matches the C99 Annex G specification for `cexp(i*phi) * r`.
