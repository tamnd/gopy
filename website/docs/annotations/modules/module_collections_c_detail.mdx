## Reading

### Block-based deque storage

`deque` allocates memory in fixed-size blocks of `BLOCKLEN=64` items. Each
block is a simple array of `PyObject*` pointers linked into a doubly-linked
list. `leftblock`/`rightblock` point to the active end blocks; `leftindex` and
`rightindex` track the first and last live slots within those blocks.

```c
// CPython: Modules/_collectionsmodule.c:40 block definition
#define BLOCKLEN 64
#define CENTER ((BLOCKLEN - 1) / 2)

typedef struct BLOCK {
    struct BLOCK *leftlink;
    PyObject *data[BLOCKLEN];
    struct BLOCK *rightlink;
} block;
```

Append to the right is O(1) unless `rightindex == BLOCKLEN - 1`, in which case
a new block is allocated and linked in.

### deque_rotate

Rotation moves items from one end to the other, reusing the block pointer
arithmetic. For rotations larger than `BLOCKLEN`, it moves whole blocks
rather than individual items.

```c

{
    ...
    while (n > 0) {
        item = deque_pop(deque, NULL);
        ...
        rv = deque_appendleft(deque, item);
        ...
        n--;
    }
```

For large `n`, CPython uses a block-pointer swap that avoids touching each
element; the snippet above is the simplified single-element path.

### defaultdict missing key

`defaultdict.__missing__` is called by the inherited `dict.__getitem__` when a
key is absent. It invokes `default_factory` with no arguments, stores the
result under the missing key, and returns it.

```c

    return value;
}
```

## gopy notes

- gopy's deque port is in `objects/` and uses a Go slice of fixed-size arrays
  to mimic the block structure. `BLOCKLEN=64` is preserved so cache-line
  behaviour matches.
- `deque_rotate` with `n >= len` is defined as equivalent to `n % len`
  rotations; gopy normalizes `n` before the loop.
- `defaultdict` is a thin wrapper around `objects.Dict`; the `__missing__`
  hook is wired through `dict_subscript` in `objects/dict.go`.
- `deque_item` is intentionally O(n); gopy does not add an index cache.

## CPython 3.14 changes

- `deque.__class_getitem__` was added for PEP 585 generic alias support
  (`deque[int]`). The C implementation delegates to `Py_GenericAlias`.
- `defaultdict` now preserves keyword arguments in `__copy__` and
  `__deepcopy__`, fixing a long-standing inconsistency with `dict` subclasses.
- Thread-safety annotations were added throughout `deque` operations under the
  free-threaded build; individual append/pop operations on the same end are now
  documented as atomic.
