`_operatormodule.c` implements `operator` as a thin C wrapper around the
CPython abstract object API. Most functions are one-liners that call
`PyNumber_*`, `PyObject_*`, or `PySequence_*` and return the result. The
interesting complexity lives in `attrgetter`, `itemgetter`, and
`methodcaller`, which are proper callable objects with `__call__` and
`__reduce__`.

## Reading

### Arithmetic and comparison wrappers

Every operator function follows the same pattern: validate argument count,
call the matching abstract API function, return the result. The macro
`BINARY_OP` generates most of them.

```c
// CPython: Modules/_operatormodule.c:78 operator_add_impl
static PyObject *
operator_add_impl(PyObject *module, PyObject *a, PyObject *b)
{
    return PyNumber_Add(a, b);
}
```

`operator.index` maps to `PyNumber_Index`, which enforces the `__index__`
protocol and rejects floats, unlike `int()`.

```c
// CPython: Modules/_operatormodule.c:201 operator_index_impl
static PyObject *
operator_index_impl(PyObject *module, PyObject *a)
{
    return PyNumber_Index(a);
}
```

### attrgetter with dotted names

When the attribute name contains a dot, `attrgetter_new` splits it on `.` and
stores a tuple of name parts. `attrgetter_call` iterates the tuple, calling
`PyObject_GetAttr` once per segment.

```c
// CPython: Modules/_operatormodule.c:414 attrgetter_call
static PyObject *
attrgetter_call(attrgetterobject *ag, PyObject *args, PyObject *kw)
{
    PyObject *obj = PyTuple_GET_ITEM(args, 0);
    ...
    for (i = 0; i < ag->nattrs; i++) {
        PyObject *attr = PyTuple_GET_ITEM(ag->attr, i);
        obj = PyObject_GetAttr(obj, attr);
        ...
    }
    return obj;
}
```

A plain (non-dotted) `attrgetter` stores a single string rather than a tuple,
so the common case avoids the loop entirely.

### itemgetter and methodcaller

`itemgetter` wraps `PyObject_GetItem`. When constructed with multiple items it
returns a tuple; with one item it returns the item directly.

```c
// CPython: Modules/_operatormodule.c:560 itemgetter_call
    if (ig->nitems == 1) {
        return PyObject_GetItem(obj, ig->item);
    }
    ...
    for (i = 0; i < ig->nitems; i++) {
        result = PyObject_GetItem(obj, PyTuple_GET_ITEM(ig->items, i));
        PyTuple_SET_ITEM(retval, i, result);
    }
    return retval;
```

`methodcaller` stores a name and a pre-built `args` tuple plus `kwargs` dict.
Its `__call__` looks up the named method via `PyObject_GetAttr`, then calls it
with the stored arguments merged with any extra ones passed at call time.

## gopy notes

- All `op_*` wrappers are generated via `compile/codegen_stmt.go` from the
  method table; there is no hand-written Go for these.
- `attrgetter` dotted-name splitting is replicated in `module/operator/` using
  `strings.Split`.
- `operator.contains` calls `PySequence_Contains`, which returns `-1` on error,
  `0` for absent, `1` for present. gopy maps this to `(bool, error)`.
- `methodcaller.__reduce__` reconstructs itself as
  `methodcaller(name, *args, **kwargs)`. The gopy port must implement
  `__reduce__` to pass pickle round-trip tests.

## CPython 3.14 changes

- `operator.call` was promoted from a provisional function to a stable public
  API; its C implementation now appears directly in the method table rather
  than behind a `#ifdef`.
- `attrgetter`, `itemgetter`, and `methodcaller` each gained `__class_getitem__`
  for PEP 585 subscript support, delegating to `Py_GenericAlias`.
- `operator.matmul` and `operator.imatmul` (in-place matrix multiply) are now
  covered by the shared `BINARY_OP` macro path rather than hand-written
  functions, reducing code size.
