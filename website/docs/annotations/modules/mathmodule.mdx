# `Modules/mathmodule.c`

<CpyLink path="Modules/mathmodule.c" />

`mathmodule.c` is the C implementation of the `math` standard-library module.
It wraps the C99 `<math.h>` functions for floating-point arithmetic and adds
several higher-level operations that CPython implements directly in C for
exactness or performance.

The file splits naturally into three groups. The first group is the IEEE 754
wrappers: `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `atan2`, `exp`, `log`,
`log2`, `log10`, `sqrt`, `hypot`, `pow`, `fabs`, `fmod`, `modf`, `frexp`,
`ldexp`, `copysign`, `ceil`, `floor`, `trunc`, `erf`, `erfc`, `gamma`, and
`lgamma`. Each of these is a thin wrapper that converts Python floats to C
`double`, calls the C99 function, handles domain errors (setting the right
Python exception for `ValueError` or `OverflowError`), and converts the result
back. Most are generated via Argument Clinic macros.

The second group covers exact-integer operations: `factorial`, `gcd`, `lcm`,
`comb`, and `perm`. These work on `PyLong` objects directly and never pass
through `double`, which avoids the rounding that would occur for large integers.

The third group holds two specialised summation routines: `fsum`, which
implements Shewchuk's compensated summation algorithm to return a result
correctly rounded to the nearest float, and `prod`, a variadic product with
fast paths for integer and float inputs.

### `math_1` wrapper pattern and domain-error handling (lines 120 to 400)

<CpyLink path="Modules/mathmodule.c" lines="120-400" />

Almost every single-argument float function is generated by the `math_1` macro
or a close variant. The macro calls a C99 function and then translates C
`errno` / IEEE 754 exceptional values into Python exceptions:

```c
static PyObject *
math_1(PyObject *arg, double (*func) (double), int can_overflow)
{
    double x, r;
    x = PyFloat_AsDouble(arg);
    if (x == -1.0 && PyErr_Occurred())
        return NULL;
    errno = 0;
    r = (*func)(x);
    if (Py_IS_NAN(r) && !Py_IS_NAN(x)) {
        PyErr_SetString(PyExc_ValueError,
            "math domain error");
        return NULL;
    }
    if (Py_IS_INFINITY(r) && Py_IS_FINITE(x)) {
        if (can_overflow)
            PyErr_SetString(PyExc_OverflowError,
                "math range error");
        else
            PyErr_SetString(PyExc_ValueError,
                "math domain error");
        return NULL;
    }
    if (errno && is_error(r))
        return NULL;
    return PyFloat_FromDouble(r);
}
```

The `can_overflow` flag distinguishes functions where a finite input
legitimately produces infinity (`exp`, `pow`) from those where infinity would
indicate a domain error (`sqrt` of a negative). `is_error` inspects `errno`
for `EDOM` and `ERANGE` as a fallback for platforms that do not set IEEE 754
exception flags reliably.

`math_log_impl` is slightly different: when called as `math.log(x, base)` it
computes `loghelper(x) / loghelper(base)` using either `log` or `log2` or
`log10` depending on the base, to preserve precision for the common cases
`log(x, 2)` and `log(x, 10)`.

### `math_fsum_impl`: Shewchuk compensated summation (lines 700 to 1000)

<CpyLink path="Modules/mathmodule.c" lines="700-1000" />

`fsum` produces a correctly-rounded sum of a sequence of floats. The core
algorithm maintains a list `partials` of non-overlapping floats whose exact
sum equals the running total. Adding each new value calls `xsum_add_value`,
which performs Neumaier/Shewchuk two-sum corrections:

```c
static int
xsum_add_value(PyObject *x_obj, PartialSum *ps)
{
    double x = PyFloat_AS_DOUBLE(x_obj);
    Py_ssize_t i, j, n = ps->n;
    double *p = ps->ps;

    for (i = j = 0; j < n; j++) {
        double y = p[j];
        double hi = x + y;
        /* two_sum: extract the rounding error */
        double lo = fabs(x) < fabs(y) ? x - (hi - y) : y - (hi - x);
        if (lo != 0.0)
            p[i++] = lo;
        x = hi;
    }
    ps->n = i;
    /* grow partials if necessary */
    p[ps->n++] = x;
    return 0;
}
```

The `two_sum` step (the `lo = ...` line) recovers the exact rounding error
from the floating-point addition `hi = x + y`. The error is kept in `partials`
instead of being discarded. At the end `xsum_round` folds `partials` from
largest to smallest, applying one final round-to-even correction. The result
is bit-for-bit identical to what you would get with infinite-precision
arithmetic followed by a single rounding step.

### `math_factorial_impl`: exact integer factorial (lines 1000 to 1300)

<CpyLink path="Modules/mathmodule.c" lines="1000-1300" />

`factorial(n)` rejects floats, negative integers, and non-integers, then
computes the product iteratively using `PyLong` arithmetic:

```c
static PyObject *
math_factorial_impl(PyObject *module, PyObject *arg)
{
    PyObject *result, *factor;
    Py_ssize_t i, n;

    /* ... validate: integer, non-negative, fits Py_ssize_t ... */
    n = PyLong_AsSsize_t(arg);

    result = PyLong_FromLong(1);
    for (i = 2; i <= n; i++) {
        factor = PyLong_FromSsize_t(i);
        PyObject *tmp = PyNumber_Multiply(result, factor);
        Py_DECREF(result);
        Py_DECREF(factor);
        result = tmp;
        if (result == NULL) return NULL;
    }
    return result;
}
```

Because the loop uses `PyLong` multiply, the result is exact for any `n`
that fits in memory. CPython 3.14 uses a divide-and-conquer helper for large
`n` (splitting the range into halves and multiplying the halves together
recursively) to reduce the number of big-integer multiplications from O(n)
to O(n log n). The simple iterative form above is the conceptual model;
the actual implementation delegates to `_PyLong_Factorial` in
`Objects/longobject.c`.

### `math_comb_impl` and `math_perm_impl`: combinatorics (lines 1600 to 2000)

<CpyLink path="Modules/mathmodule.c" lines="1600-2000" />

`comb(n, k)` computes the binomial coefficient without computing factorials
separately. It uses the identity C(n, k) = C(n, n-k) to ensure `k <= n/2`,
then iterates:

```c
static PyObject *
math_comb_impl(PyObject *module, PyObject *n, PyObject *k)
{
    /* ... validate: integers, 0 <= k <= n ... */
    /* use smaller k */
    if (PyObject_RichCompareBool(k, n_minus_k, Py_GT))
        k = n_minus_k;

    result = PyLong_FromLong(1);
    for (Py_ssize_t i = 0; i < ki; i++) {
        /* result = result * (n - i) // (i + 1) */
        factor = PyNumber_Subtract(n, PyLong_FromSsize_t(i));
        result = PyNumber_Multiply(result, factor);
        divisor = PyLong_FromSsize_t(i + 1);
        result = PyNumber_FloorDivide(result, divisor);
        /* ... */
    }
    return result;
}
```

The intermediate `result * (n - i)` is always divisible by `i + 1` because
the product of any `i+1` consecutive integers is divisible by `(i+1)!`. This
guarantees the integer division is exact at every step with no remainder,
keeping intermediate values as small as possible.

`perm(n, k)` is simpler: it computes the falling factorial `n * (n-1) * ... *
(n-k+1)` as a straight `PyLong` product loop, using the same integer-exactness
property.
