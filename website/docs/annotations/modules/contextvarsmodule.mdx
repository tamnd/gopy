# `Modules/_contextvarsmodule.c`

<CpyLink path="Modules/_contextvarsmodule.c" />

A thin C glue file. The real implementation of context variables lives in
`Python/context.c`; this file does nothing beyond registering the three
public types (`ContextVar`, `Context`, `Token`) with the module and
forwarding each method call to the corresponding `PyContextVar_*` or
`PyContext_*` C API function.

`Lib/contextvars.py` re-exports everything from `_contextvars`, so user code
sees the C-backed types from day one without any Pure-Python fallback path.

The file is short enough that every non-trivial function maps to a single
Argument Clinic `/*[clinic input]*/` block and a one-line body.

### Module method table and type registration (lines 140 to 200)

<CpyLink path="Modules/_contextvarsmodule.c" lines="140-200" />

The module init function registers three C types by calling `PyType_Ready`
and then `PyModule_AddType` for each:

```c
static int
_contextvars_exec(PyObject *module)
{
    if (PyModule_AddType(module, &PyContextVar_Type) < 0)   return -1;
    if (PyModule_AddType(module, &PyContext_Type) < 0)      return -1;
    if (PyModule_AddType(module, &PyContextToken_Type) < 0) return -1;
    return 0;
}
```

The type objects themselves (slots, `tp_methods`, `tp_new`, `tp_repr`,
`tp_hash`) are defined in `Python/context.c`. This file only imports and
re-registers them; it adds no methods of its own beyond the Argument Clinic
wrappers.

### `contextvar_set` token creation (lines 40 to 90)

<CpyLink path="Modules/_contextvarsmodule.c" lines="40-90" />

`ContextVar.set(value)` returns a `Token` that remembers the previous value
(or `Token.MISSING` if there was none):

```c
static PyObject *
_contextvars_ContextVar_set_impl(PyContextVar *self, PyObject *val)
{
    return PyContextVar_Set((PyObject *)self, val);
}
```

`PyContextVar_Set` (in `Python/context.c`) walks the current context HAMT
to find the old value, creates a `Token` capturing it, and writes the new
value into the context. The token is the only way to undo the `set` via
`reset`.

### `context_run` (lines 90 to 140)

<CpyLink path="Modules/_contextvarsmodule.c" lines="90-140" />

`Context.run(callable, *args, **kwargs)` activates the context for the
duration of the call:

```c
static PyObject *
_contextvars_Context_run_impl(PyContext *self, PyObject *callable,
                               PyObject *args, PyObject *kwargs)
{
    if (PyContext_Enter((PyObject *)self) < 0)
        return NULL;

    PyObject *result = PyObject_Call(callable, args, kwargs);

    if (PyContext_Exit((PyObject *)self) < 0) {
        Py_XDECREF(result);
        return NULL;
    }
    return result;
}
```

`PyContext_Enter` pushes the context onto the thread-state's context stack
so that `ContextVar.get()` calls inside `callable` see the values stored in
this context. `PyContext_Exit` pops it. The exit is always called even when
`callable` raises, matching the semantics of a `with` block.

In gopy, `module/contextlib/module.go` replicates the enter/exit pair
around the `callable` invocation using the same HAMT-backed context
implementation.
