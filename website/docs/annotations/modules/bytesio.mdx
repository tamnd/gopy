# `Modules/_io/bytesio.c`

<CpyLink path="Modules/_io/bytesio.c" />

`bytesio.c` implements `BytesIO`, the in-memory binary I/O class. A
`BytesIO` object wraps a single `bytes` buffer and exposes the complete
`BufferedIOBase` interface: `read`, `write`, `seek`, `tell`, `truncate`,
`getvalue`, and `getbuffer`.

Unlike `BufferedReader`/`BufferedWriter`, there is no separate raw layer.
The buffer is the entire backing store. `string_size` tracks the logical
length of the stored data; `pos` tracks the current read/write cursor.
The underlying allocation (`buf`) may be larger than `string_size` if the
object was truncated without being reallocated.

The main complication is buffer-view export: `getbuffer()` hands out a
`Py_buffer` that gives the caller a direct pointer into `buf`. While at
least one such view is live, the object is "exported" and any operation
that would resize or replace `buf` (write past the end, truncate) is
forbidden and raises `BufferError`.

## Reading

### Buffer layout (lines 1 to 80)

<CpyLink path="Modules/_io/bytesio.c" lines="1-80" />

The internal state struct is compact:

```c
typedef struct {
    PyObject_HEAD
    PyObject *buf;          /* PyBytesObject holding the data */
    Py_ssize_t pos;         /* current stream position */
    Py_ssize_t string_size; /* logical size (may be < len(buf)) */
    Py_ssize_t exports;     /* number of active Py_buffer views */
    PyObject *dict;         /* instance __dict__ (for subclasses) */
    PyObject *weakreflist;
} bytesio;
```

`buf` is a `PyBytesObject` rather than a raw C array. This lets
`getvalue()` return a slice without a copy: when `pos == 0` and
`string_size == len(buf)`, `getvalue` can return `buf` directly. Otherwise
it calls `PyBytes_FromStringAndSize(PyBytes_AS_STRING(self->buf), self->string_size)`.

`string_size` can fall below `len(buf)` only after `truncate()`. The extra
allocated bytes are not reclaimed immediately; the buffer is shrunk lazily
on the next write or when `__sizeof__` is inspected.

### `bytesio_write` resize path (lines 80 to 280)

<CpyLink path="Modules/_io/bytesio.c" lines="80-280" />

The write implementation must handle three cases: the new data fits within
the existing allocation, the buffer must grow, and the object is currently
exported (mutation forbidden):

```c
static PyObject *
_io_BytesIO_write_impl(bytesio *self, Py_buffer *b)
{
    Py_ssize_t end_pos = self->pos + b->len;

    CHECK_EXPORTS(self);  /* raise BufferError if exports > 0 */

    if (end_pos > PyBytes_GET_SIZE(self->buf)) {
        if (unshare_buffer(self, Py_MAX(end_pos, self->string_size)) < 0)
            return NULL;
    }
    if (self->pos > self->string_size) {
        /* Gap between string_size and pos: fill with NUL. */
        memset(PyBytes_AS_STRING(self->buf) + self->string_size,
               0, self->pos - self->string_size);
    }
    memcpy(PyBytes_AS_STRING(self->buf) + self->pos,
           b->buf, b->len);
    self->pos = end_pos;
    if (end_pos > self->string_size)
        self->string_size = end_pos;
    ...
}
```

`unshare_buffer` calls `_PyBytes_Resize` on `self->buf` to grow the
allocation. If `buf` is shared (reference count > 1), which can happen
after pickling, `_PyBytes_Resize` will allocate a fresh object; `unshare_buffer`
handles this by replacing `self->buf` with the new object.

Writing past `string_size` without a prior seek leaves a gap, which is
zero-filled by the `memset` before the `memcpy`. This matches the behavior
documented in the `io` module: seeking past the end and writing fills the
intervening bytes with zero.

### `bytesio_getvalue` and the view export guard (lines 600 to 820)

<CpyLink path="Modules/_io/bytesio.c" lines="600-820" />

`getvalue()` always returns a `bytes` object containing the full logical
content regardless of the current `pos`:

```c
static PyObject *
_io_BytesIO_getvalue_impl(bytesio *self)
{
    if (self->string_size == 0)
        return PyBytes_FromStringAndSize(NULL, 0);
    if (self->pos == 0 &&
        PyBytes_GET_SIZE(self->buf) == self->string_size)
        return Py_NewRef(self->buf);  /* return buf directly, no copy */
    return PyBytes_FromStringAndSize(PyBytes_AS_STRING(self->buf),
                                      self->string_size);
}
```

`getbuffer()` exports the raw backing memory as a `Py_buffer`:

```c
static int
bytesio_getbuffer(bytesio *self, Py_buffer *view, int flags)
{
    CHECK_EXPORTS_INIT(self);
    int ret = PyBuffer_FillInfo(view, (PyObject *)self,
                                PyBytes_AS_STRING(self->buf),
                                self->string_size, 0, flags);
    if (ret == 0)
        self->exports++;
    return ret;
}
```

While `exports > 0`, the `CHECK_EXPORTS` macro at the top of `write` and
`truncate` raises `BufferError: Existing exports of data: object cannot be
re-sized`. This protects the buffer pointer handed to the caller from
becoming dangling if a resize were to reallocate `buf`.

`releasebuffer` decrements `exports`. When `exports` returns to zero,
resize operations are permitted again. This protocol mirrors the buffer
protocol used by `array.array` and `memoryview`.
