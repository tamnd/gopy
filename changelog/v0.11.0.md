# v0.11.0 - 2026-05-07

The specializer and monitor drop. v0.11 lights up the two big
runtime features 3.12 / 3.13 added: the PEP 659 adaptive
specializer that rewrites bytecode into typed variants on first
hit, and PEP 669's `sys.monitoring` instrumentation surface that
fans 19 events out to up to seven tools without paying a per-event
cost when no tool is listening. The legacy `sys.settrace` /
`sys.setprofile` callbacks now ride on top of the same monitor
fan-out, so a single dispatch path drives both shapes.

## Shipped

### `specialize/`

* `backoff.go`, `cache.go`. Counter and inline-cache layouts.
  Counters track success/fail with the
  `value | (backoff << 4) | tag` packing from
  `Include/internal/pycore_backoff.h`; the cache helpers walk
  per-opcode `CacheCount` slots after the prefix codeunit.
* `quicken.go`. Port `_PyCode_Quicken`. Walks bytecode at code
  object install time and rewrites eligible opcodes to their
  adaptive variants, seeding the counters.
* `core.go`, `deopt.go`. `_PyOpcode_Caches` and `_PyOpcode_Deopt`
  tables plus `set_opcode` / `specialize` / `unspecialize` core
  helpers from `Python/specialize.c`.
* Per-family ports of every PEP 659 specializer in
  `Python/specialize.c`:
  `LOAD_ATTR` (module / class / instance / slot / property /
  method arms), `STORE_ATTR`, `LOAD_GLOBAL`, `LOAD_SUPER_ATTR`,
  `BINARY_OP` (add / subtract / multiply for int / float / unicode
  / list / dict), `COMPARE_OP`, `CONTAINS_OP`, `TO_BOOL`,
  `STORE_SUBSCR`, `UNPACK_SEQUENCE`, `FOR_ITER` (list / tuple /
  range / generator), `SEND`, `CALL`, `CALL_KW`. Each family lands
  with its hit / miss / deopt path and the type-version /
  dict-keys-version checks the fast variants assume.
* `objects/exact.go`, `objects/version.go`,
  `objects/type_specialize.go`, `objects/dict_specialize.go`. The
  exact-type predicates the families key off, plus the
  `tp_version_tag` and `dk_version` counters the inline caches
  store.

### `vm/`

* `adaptive.go`, `dispatch.go`. Wire the specializer into the eval
  loop. Every quickened opcode peels into the typed variant on
  hit, increments its counter, and falls back to the generic arm
  on miss with the deopt counter primed.
* `instrument_fire.go`. The 19 fire-event entry points
  (`_Py_call_instrumentation` family from
  `Python/instrumentation.c`) dispatch to the per-tool callbacks
  registered against `monitor.InterpState`.

### `monitor/`

* `events.go`, `tools.go`, `state.go`. PEP 669 event IDs and tool
  IDs (debugger=0, coverage=1, profiler=2, branch=3, optimizer=5,
  sys_profile=6, sys_trace=7), the per-code instrumentation slab,
  and the `EventSet` mask helpers.
* `interp.go`. `InterpState` carries the per-tool callback table,
  per-tool event mask, the active-tool registry, the global
  monitoring version, and the shared sentinels (`Disable`,
  `Missing`).
* `tables.go`, `install.go`. The shadow walk from
  `_Py_Instrument`. Quickened bytecode is rewritten in place to
  `INSTRUMENTED_*` variants; deinstrument restores the original
  byte. Per-event mask vs per-tool mask are recomputed lazily
  through `setup_*_callbacks` so re-registration stays cheap.
* `line.go`. Line instrumentation. Decodes the PEP 626 line table
  to mark start-of-line positions; `INSTRUMENTED_LINE` fires the
  `LINE` event for each line transition through the dispatch
  fan-out.
* `local.go`. The 11 local events that gate per-frame line and
  opcode tracing without touching the global mask.
* `fire.go`. The shared callback runner: walks the active tool
  bitmask, calls each callback in tool-id order, honours the
  `Disable` sentinel by clearing the per-code instrumentation,
  and re-raises Python exceptions back into the interpreter.
* `sysmonitoring.go`. The `sys.monitoring` builtin module:
  `use_tool_id`, `free_tool_id`, `get_tool`, `register_callback`,
  `set_events`, `get_events`, `set_local_events`,
  `get_local_events`, `restart_events`, plus the event / tool
  constants and the `DISABLE` / `MISSING` singletons. Wires
  through to `monitor.InterpState`.
* `sentinel.go`. `Disable` / `Missing` Python objects.

### `vm/` legacy tracing bridge

* `legacy_tracing.go`. Port of `Python/legacy_tracing.c`. The
  bridge registers `sys.profile` and `sys.trace` as PEP 669 tools
  6 and 7, fans the matching events through Go-level
  `LegacyTraceFunc` callbacks shaped like CPython's
  `Py_tracefunc`, and translates between the two callback
  conventions. Forward jumps return the `Disable` sentinel so the
  line handler takes over via `INSTRUMENTED_LINE`.
* `sys_trace_builtins.go`. Python-visible `sys.settrace`,
  `sys.setprofile`, `sys.gettrace`, `sys.getprofile`. Threads the
  user-supplied Python callable through a Go trampoline shaped
  like `LegacyTraceFunc`, then defers to `SetTrace` / `SetProfile`
  to install the bridge. Mirrors `Python/sysmodule.c`'s
  `sys_settrace` / `sys_setprofile`.
* `frame/frame.go`. Per-frame `TraceLines`, `TraceOpcodes`,
  `Lineno` slots so the bridge can drive line and opcode events
  without paying for them when the user has not asked. Mirrors
  the `f_trace_lines` / `f_trace_opcodes` flags on
  `PyFrameObject`.
* `state/state.go`, `monitor/interp.go`. Per-thread tracing slots
  on the VM-side thread state plus `SysProfileOnce` /
  `SysTraceOnce` flags so the one-time `setup_*_callbacks`
  install runs at most once per interpreter.

### `compile/opcodes_gen.go`

* Regenerate the opcode table from the upstream bytecode spec to
  pick up the specialized variants
  (`LOAD_ATTR_INSTANCE_VALUE`, `BINARY_OP_ADD_INT`, etc.) and the
  `INSTRUMENTED_*` mirror set. The cache-count column lines up
  with `_PyOpcode_Caches` so the dispatch loop can stride over
  the inline cache slots.

### Gates

* `vmtest/v011_gate_test.go`. End-to-end gates for the four
  surfaces:
  - `TestGateSpecializerRewritesToBool` drives a `TO_BOOL`
    through the adaptive path with a forced-zero counter, lands
    on the specialized variant, recognises the deopt path, and
    still produces `True` for an int operand.
  - `TestGateMonitorPyReturnFires` registers a debugger callback
    against `EventPyReturn`, instruments the code, runs the
    program, and checks the callback received the per-event arg
    trio.
  - `TestGateLegacyTraceFires` installs a Go-level legacy
    tracefunc, runs a small program, and confirms the bridge
    fires `PyTrace_RETURN` with the right value.
  - `TestGateSysMonitoringRoundTrip` claims a tool slot through
    `use_tool_id`, registers a Python callback through
    `register_callback`, sets events, and checks the internal
    state reflects the request.
