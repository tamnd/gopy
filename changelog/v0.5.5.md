# v0.5.5 - 2026-05-05

The parser handover. After v0.5.5 the lexer turns Python source into
a token stream, the pegen runtime carries the token buffer and
mark/restore primitives the generated parser table will lean on, the
SyntaxError text panel is in place, and string-literal escape
decoding lands.

The generated parser table itself stays out of this drop. That work
is large enough to warrant its own release and depends on the
Go-targeted PEG generator under `tools/parser_gen/` (in flight).

## Shipped

### `parser/lexer/`

* `state.go`, `buffer.go` from `Parser/lexer/state.[ch]` and
  `Parser/lexer/buffer.[ch]`. The buffer-rebase dance from the C
  source disappears in gopy because we use offsets instead of raw
  pointers.
* `lexer.go`, `token.go` from `Parser/lexer/lexer.c`. Regular-mode
  FSM, NAME / NUMBER / STRING scan, INDENT / DEDENT emission via the
  pendin counter, line continuation, paren-balance tracking,
  COMMENT / NL / type-comment emission under the extra-tokens flag.
* `fstring.go` from `Parser/lexer/lexer.c` tok_get_fstring_mode.
  PEP 701 f-string scanning plus PEP 750 t-strings: prefix
  detection, mode stack push, FSTRING_START / FSTRING_MIDDLE /
  FSTRING_END emission, brace-depth tracking with re-entry to
  fstring mode when `}` closes the expression part.
* Drivers: `driver_string.go`, `driver_file.go`,
  `driver_readline.go`. From-bytes, from-reader, and readline
  callback shapes mirroring CPython's three tokenizer entry points.
  BOM stripping on the first line lands in the string and reader
  drivers.

### `parser/pegen/`

* `parser.go` from `Parser/pegen.[ch]`. Parser struct, fillToken
  pulling from the lexer, mark / reset / peek, Expect and
  ExpectName as the consume helpers the generated table will use.
* `actions.go` from `Parser/action_helpers.c`. Sequence shape ops
  (singleton, insert-in-front, append, flatten, first / last item),
  the dotted-name joiners, SetExprContext walk over the
  Name / Tuple / List / Starred / Attribute / Subscript family, and
  the GetExprName phrase table behind "cannot assign to %s". The
  AST builder helpers (MakeArguments, decorated FunctionDef,
  JoinedStr assembly) ship alongside the generated parser.

### `parser/errors/`

* `messages.go` transcribes the SyntaxError text panel from
  `Parser/pegen_errors.c`. Goal is byte-for-byte parity with
  CPython 3.14: a SyntaxError gopy emits should be
  indistinguishable from CPython's.
* `builder.go` exposes Raise / RaiseIndent / RaiseTab / RaiseRange
  as the four constructors the parser will reach for. The
  SyntaxError record carries a Kind enum so the caller can lift
  to SyntaxError / IndentationError / TabError / OverflowError.
* `tokenizer_errors.go` is the dispatch from a lexer errcode
  to the matching message, mirroring `_Pypegen_tokenizer_error`.

### `parser/string/`

* `parse.go`, `decode.go` from `Parser/string_parser.c`. ParseString
  takes a raw string-literal token (b/u/r prefix plus single or
  triple quotes plus body), strips the wrapping, and decodes the
  body. Escape table: `\n \r \t \v \a \b \f \\ \' \"`, octal up to
  three digits, `\xNN`, `\uNNNN`, `\UNNNNNNNN`. Bytes mode rejects
  non-ASCII bytes per the C source. Raw mode and the no-backslash
  fast path bypass escape decoding.
