# v0.7.0 - 2026-05-06

The lifecycle drop. After v0.7 the runtime boots through the real
CPython init path: PyPreConfig and PyConfig parse env and CLI, the
init phases hand off to pythonrun, and `gopy -c`, `gopy script.py`,
and the bare REPL all share one entry. The builtins, sys, and
`_warnings` surface those entry points need lands alongside.

## Shipped

### `initconfig/`

* `preconfig.go` from `Python/preconfig.c`. PyPreConfig with the
  three named initializers (`PyPreConfig_InitPythonConfig`,
  `_InitIsolatedConfig`, `_InitCompatConfig`) and the env-var
  merge. The locale / coerce / utf8 fields are reserved for v0.8
  alongside the locale glue.
* `getenv.go` from `Python/getenv.c`. `_Py_GetEnv`, `_Py_str_to_int`,
  `_Py_get_env_flag`, the three readers every config helper leans on.
* `config.go` from `Python/initconfig.c`. PyConfig (the v0.7 subset
  of the C struct), plus `PyConfig_InitPythonConfig`,
  `PyConfig_InitIsolatedConfig`, and `PyConfig_InitCompatConfig`.
* `status.go` from `Python/initconfig.c`. PyStatus error / exit /
  ok constructors and the env-merge into PyConfig.
* `cmdline.go` from `Python/getopt.c` plus `Python/initconfig.c`
  `config_parse_cmdline`. The `-c` / `-m` / `-W` / `-X` panel and
  the long-option subset gopy honors today.
* `read.go` from `Python/initconfig.c` `_PyConfig_Read`. Walks the
  precedence chain (compile-time defaults, env, command line,
  explicit writes) and resolves to the final config.

### `pathconfig/`

* `pathconfig_darwin.go`, `pathconfig_unix.go` from
  `Python/getpath.c` plus the platform getpath modules. Resolves
  prefix / exec_prefix / `sys.path` from the executable's location
  with the documented fallbacks. Windows lands in v0.8.

### `lifecycle/`

* `init.go` from `Python/pylifecycle.c` `pyinit_core` and
  `pyinit_main`. Phase 1 brings the core runtime up (interpreter
  state, GIL, builtins, sys); phase 2 imports the user-facing
  modules and runs `_PyRunMain`-equivalent setup.
* `finalize.go` from `Python/pylifecycle.c` `Py_FinalizeEx`. The
  shutdown order CPython documents: registered atexit callbacks,
  module finalizers, sys teardown, GIL release.
* `main.go` from `Modules/main.c` `Py_Main`. The unified entry: read
  argv into PyConfig, init, dispatch through pythonrun, finalize.

### `pythonrun/`

* `runstring.go` from `Python/pythonrun.c` `PyRun_SimpleStringFlags`
  and `PyRun_StringFlags`. The `-c` smoke fixtures from v0.6 re-root
  here; their assertions stayed unchanged.
* `runfile.go` from `Python/pythonrun.c` `PyRun_AnyFileExFlags`. File
  open, source decode, parse, compile, eval; the file-positional
  caller in `cmd/gopy` routes through this.
* `repl.go` from `Python/pythonrun.c` `PyRun_InteractiveLoopFlags`.
  Basic READ / EVAL / PRINT loop. Readline editing and PS1 / PS2
  customization land with the readline port in v0.9.
* `dispatch.go` covers the three-arm matrix (`-c`, file, REPL) so
  `lifecycle.Main` calls a single switch rather than open-coding
  the choice.

### `errors/`

* `print.go` from `Python/pythonrun.c` `_PyErr_Print`. SystemExit
  short-circuits exit code translation; everything else renders
  through the traceback panel and writes to `sys.stderr`.

### `sys/`

* `create.go` from `Python/sysmodule.c` `_PySys_Create`. Builds the
  module dict and stamps the static attributes that don't depend on
  PyConfig (`maxsize`, `byteorder`, `int_info`, etc.).
* `config_attrs.go` and `flags.go` stamp the PyConfig-driven slice:
  `sys.argv`, `sys.path`, `sys.path0`, `sys.executable`, the
  `sys.flags` named tuple, `sys.warnoptions`, `sys.dont_write_bytecode`.
* `runtime.go` from `Python/sysmodule.c`. `sys.exit`, `getrecursionlimit`
  / `setrecursionlimit`, `getrefcount` (always 1 in gopy),
  `intern`, `gettrace` / `settrace`, `getfilesystemencoding`.
* `implementation.go` pins `sys.implementation` to the gopy-specific
  fields: `name = "gopy"`, `cache_tag = "gopy-3140"`, `version`,
  `hexversion`.

### `builtins/`

* `iter.go` from `Python/bltinmodule.c`. The iteration panel: `iter`,
  `next`, `enumerate`, `zip`, `range`, `reversed`, `map`, `filter`.
* `reflect.go` from `Python/bltinmodule.c`. The reflection panel:
  `type`, `isinstance`, `issubclass`, `id`, `hash`, `repr`, `len`,
  `callable`.
* `attrs.go` from `Python/bltinmodule.c`. The attribute panel:
  `getattr`, `hasattr`, `setattr`, `delattr`. `vars` and `dir` are
  parked behind frame-locals access in v0.8.
* `aggregate.go` from `Python/bltinmodule.c`. The aggregation panel:
  `sum`, `min`, `max`, `any`, `all`, `sorted`. The `key=` and
  `default=` kwargs match CPython behavior; `sorted(reverse=True)`
  inverts the comparison.
* `numeric.go` from `Python/bltinmodule.c`. The numeric / format
  panel: `abs`, `divmod`, `pow`, `chr`, `ord`, `bin`, `oct`, `hex`,
  `ascii`, `format`. Routes through the `format/` package for the
  `[[fill]align][sign][...][type]` mini-language.
* `ctor.go` from `Python/bltinmodule.c`. The constructor wrappers:
  `int`, `float`, `bool`, `list`, `tuple`, `dict`. PEP 515 underscore
  stripping in `int(...)` parsing. `set` / `frozenset` wait on the
  set type in objects.

### `warnings/`

* `filters.go` and `warnings.go` from `Python/_warnings.c`. The
  Action / Category / Filter model, `defaultFilters` seed (matches
  `_PyWarnings_InitState`), and `_Py_Warn` dispatch. Categories use
  a Go struct hierarchy with a Parent pointer until the warning
  class machinery lands with the type port.
* `registry.go` ports the per-module `__warningregistry__` dedup.
  `ActionOnce` shares a synthetic `__once__` bucket so dedup is
  global across modules; the other narrowing actions key by
  (action, category, message, module, lineno) shape.
* `api.go` ports the user-facing `simplefilter`, `filterwarnings`,
  `resetwarnings` from `Lib/_py_warnings.py`. Action validation,
  the lineno guard, and the `_add_filter` dedup-and-prepend
  semantics with optional `append=True`.

## Pending for v0.8

* `import` and the source-encoding handshake. `gopy -m foo` returns
  `ErrNotImplemented` until the import system lands.
* Sub-interpreters and `Py_NewInterpreter`. The thread-state and
  interpreter-state machinery is in place but only one runs.
* `compile` / `exec` / `eval` builtins beyond the smoke wrappers.
* Windows `pathconfig`. Darwin and Linux are covered.
* PEP 657 caret pinning in tracebacks. v0.7 still emits file:line:col
  only.
* The remaining bytecode handlers parked behind future spec blocks
  (LOAD_SPECIAL / LOAD_SUPER_ATTR, IMPORT_NAME / FROM / STAR,
  SETUP_FINALLY / WITH_EXCEPT_START / CLEANUP_THROW / BEFORE_*_WITH,
  CHECK_EG_MATCH / LOAD_ASSERTION_ERROR, YIELD_VALUE / SEND /
  GET_AWAITABLE / RETURN_GENERATOR, MATCH_*).
